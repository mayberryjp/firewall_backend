# Frontend handoffs - 2026-11-08

## 2026-11-08-01 Conntrack controls

- **Priority:** medium.
- **Classification:** required frontend controls, validation and safety messaging.
- **Status:** Pending frontend review.
- **Backend availability:** Unreleased working tree; not committed, published or deployed.
- **Contract/recommended release:** additive; next automatic calendar version.

### Exact contract and affected requests

Previously conntrack keys were unsupported. The existing kernel string maps now
accept nine keys: host-global `net.netfilter.nf_conntrack_max` (1024..16777216
entries), and namespace TCP established/close/close-wait/fin-wait/last-ack/time-wait
and UDP unreplied/stream timeout keys (1..604800 seconds). The
[canonical spec](../../FRONTEND_SPEC.md#conntrack-limits-and-timeouts) lists every
full name. No new fields, nullability/default changes or separate write API.
Values must be nonnull canonical decimal strings, not JSON numbers.

Affected methods/paths:

- `GET /api/v1/kernel/tunables/catalog`: existing array adds nine integer entries
  with scope, inclusive min/max, count 1 and warnings. Requires API key and
  `state.read`.
- `GET /api/v1/kernel/tunables`, `GET /api/v1/runtime`,
  `GET /api/v1/state`, `GET /api/v1/revisions/latest` and
  `GET /api/v1/revisions/{revision}`: preserve these keys in their existing
  kernel maps; runtime inspection distinguishes applied/observed/original values.
  Requires `state.read`.
- `POST /api/v1/transactions`: full candidate, current `base_revision`,
  confirmation timeout 10..300 seconds. Requires `transactions.write` plus
  `kernel.host.write` for entry limits and/or `kernel.namespace.write` for
  timeouts, and other changed-resource permissions.
- `POST /api/v1/transactions/{id}/confirm`, `/rollback` and
  `POST /api/v1/revisions/{revision}/restore`: existing permissions/workflow apply.

Small valid synthetic fragment only; not a full request or recommendation:

```json
{"kernel":{"host":{"net.netfilter.nf_conntrack_max":"65536"},"namespace":{"net.netfilter.nf_conntrack_tcp_timeout_established":"432000","net.netfilter.nf_conntrack_udp_timeout":"30"}}}
```

Type/null errors `400`; wrong scope, noncanonical/out-of-range or unsupported
keys `422`; authentication/permissions `401`/`403`; stale/busy `409`; native
preflight/write/readback failures use existing `500`; observation unavailability
`503`. Submit `202` remains provisional, confirm/rollback `200`.

### Frontend work and deployment

Add an advanced conntrack group, using catalog scope and bounds instead of a
hard-coded sysctl allowlist. Preserve string serialization, full candidate
submission, draft retention on failure and uncertain-write inspection. Display
configured/effective/captured-original values distinctly; empty maps are not
zero defaults. Support removing ownership rather than restoring a guessed value.

Show memory/connection warnings before confirmed apply: larger capacity permits
more memory use, lower limits can block new connections, short timeouts can expire
idle flows or cause late teardown drops. Bounds are not RAM sizing advice.
No automatic recommendation/apply/confirmation, connection flushing, hash-bucket
resizing or TCP validation relaxation. Do not promise restored settings recover
expired flows or that every existing timeout changes immediately.

Deploy the accepting backend before exposing submissions with the new keys.
No migration, compatibility window or state reset. Linux needs loaded conntrack
sysctls and writable procfs. The maximum is host-global and uses exclusive
host-tunables ownership; explicit lab namespaces need the existing host-tuning
opt-in. Timeout settings affect only the daemon's network namespace.
Missing/unwritable keys and unsupported current values fail explicitly.

### Acceptance and validation

Verify all nine catalog entries and units, boundary values and canonical strings;
reject wrong scopes, JSON numbers/null, zero, leading zeros, out-of-range values
and writable-count/bucket/TCP-relaxation attempts. Check separate host/namespace
permissions, provisional apply, confirm, saved/reopened values, removal and
rollback. Verify independent traffic before confirmation on a representative
Linux firewall, including that settings do not deliberately flush connections.

## 2026-11-08-02 Discord first-seen drop alerts

- **Priority:** medium.
- **Classification:** required settings/credential types, forms and status/error UI.
- **Status:** Pending frontend review.
- **Backend availability:** Unreleased working tree; not committed, released or deployed.
- **Contract/recommended release:** additive API/configuration and private-state
  deployment requirement; next automatic calendar version.

### Exact behavior and affected methods

Previously no Discord delivery existed. New `config.discord` is nonnull
`{enabled:boolean,webhook_ref:string}`, default disabled with an empty reference.
The URL is a secret credential and is **not** saved in config, revisions or
exports. Private references are device-local, 32 lowercase hexadecimal characters;
enabled configuration requires an available reference.

- `POST /api/v1/services/discord/webhooks`, API key and `discord.write`:
  no query; exactly `{webhook_url:string}`. Canonical HTTPS
  `discord.com/api/webhooks/ID/TOKEN`, <=512 bytes, nonzero digit ID <=20 characters,
  token 16..256 ASCII letters/digits/underscore/hyphen; no explicit port,
  credentials, escaping, query or fragment. Returns `201 {webhook_ref:string}`.
  Upload does not enable or send. No secret read/delete/test-send endpoint.
- `POST /api/v1/transactions`, `/api/v1/transactions/{id}/confirm`, `/rollback`
  and `POST /api/v1/revisions/{revision}/restore`: normal full-candidate/base
  revision/10..300-second confirmed workflow; `transactions.write` and
  `discord.write`, plus permissions for other changed areas.
- `GET /api/v1/state`, `/api/v1/revisions/latest` and
  `/api/v1/revisions/{revision}` (`state.read`): new `discord` configuration,
  only the private reference, never the URL.
- `GET /api/v1/services/discord/status`, API key and `state.read`: no query/body.
  `enabled:boolean`, `state` enum
  `starting|disabled|simulated|unavailable|paused|ready|error|stopped`,
  decimal-string alert-entry counters `delivered`/`failed`,
  nullable-string `last_drop_id`/`error`, `counters_scope:"daemon_session"` and
  exact `deduplication:["source","destination","destination_port","protocol"]`.
  Counts are not packet counts; status contains no URL/token.
- `POST /api/v1/processes/restart`, `{"target":"discord"}`, `system.restart`:
  existing `202` managed-runner scheduling and restart/error UX. Health/task
  inspection includes the new manager. Restart does not enable or reset dedup.

Authentication/permission failures `401`/`403`; wrong methods `405`; invalid
JSON/type/null/URL/query `400`; semantic config or unavailable/missing reference
`422`; active transactions/upgrades `409`; manager/private storage unavailable
or 256-webhook limit `503`. Transaction results remain provisional `202`,
confirm/rollback `200`, existing native failures `500`.

Synthetic fragment only; substitute the real **reference**, not a raw URL:

```json
{"discord":{"enabled":true,"webhook_ref":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}}
```

### First-ever identity and delivery

Identity is exactly source IP, destination IP, destination port and numeric IP
protocol. Source ports, chain/reason/interfaces/rulesets do not produce repeat
alerts. Null port is distinct from zero. The permanent exact-key native SQLite
index survives daemon restart and rotating-log eviction. No time expiry, clear
endpoint or auto-eviction. It indexes captured tuples even while disabled;
enabling never backfills them or existing history. Initial retained history seeds
the index without notification; pre-feature already-evicted history is unknowable.

One first occurrence becomes one message entry; up to ten entries can share one
Discord message. Include configured hostname, source/destination/ports, protocol,
chain/reason, interface names, first drop ID, epoch-ms timestamp and byte length;
no packet payload or secret. Mentions are disabled.

Only committed settings send; configuration/upgrade work pauses delivery.
Native Linux host mode only; simulator never posts. HTTP delivery verifies TLS,
uses a fixed provider, no redirects and 5s connect/10s total timeout. Explicit
Discord 429 responses retry at most three times after their bounded
0..86400-second retry delay. Invalid rate-limit responses fail visibly.
Shutdown/setting changes cancel waits/requests promptly.

Delivery is best-effort, not guaranteed exactly once. Queue claims are durable
before HTTP to avoid duplicate replay after uncertain outcomes. Transport,
non-429 errors, interrupted sends and configuration changes are not automatically
replayed; repeated packets for failed tuples remain suppressed. Disabling clears
pending delivery without forgetting identities. Pending unclaimed first records
survive restart. A previously accepted Discord message cannot be rolled back.

### Frontend tasks and deployment

Add a global toggle and password-style webhook URL field with a replace-existing
state. Upload privately, clear the raw input after success, then stage the returned
reference in the full candidate and use normal confirmed apply. Never fetch,
cache, log, export or echo the URL/token, including analytics or validation errors.
Add `discord.write` to permission controls; preserve drafts and explicitly show
upload versus provisional apply versus confirmed enabled states.

Show the exact permanent tuple definition and no-history/disabled backfill rule.
Explain that enabling exports drop metadata to Discord; require operator approval
for that destination. Render failed-entry counters and sanitized errors honestly;
retrying enable/restart does not resend already seen tuples. Poll status for the
settings/status view and add both routes to the API Explorer.

Deploy backend support first. Private URL files live beside daemon state in the
`.discord` directory; the index is `first-seen.sqlite` in the native deny-log
directory. Back up/protect both with private state. The index/queued first records
grow with distinct traffic and must not be silently truncated; monitor disk space.
The bundled SQLite dependency adds no external database service or OS SQLite
package. Preserve existing native NFLOG privileges/storage and firewall
DNS/routes/outbound HTTPS reachability. No automatic firewall permit, reset,
migration or compatibility window. Use HTTPS management or protected local control
for URL upload.

### Acceptance and backend validation

repeat; a change in any identity field must be distinct. Test duplicate packets
within a batch, retention rotation, restart, disabled observations and no backfill.
Verify payload/mentions/bounds, provider-only URLs, 429 delay/retry and cancellation.
