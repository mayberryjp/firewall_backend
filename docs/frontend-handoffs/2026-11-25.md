# 2026-11-25

## 2026-11-25-01 Browser-compatible Sando policy mapping

- Priority: high. Classification: **required**. Status: **Pending frontend review**.
- Backend availability: unreleased working-tree changes; not deployed or delivered.
- Contract impact: mapping/error contract fix, including expanded explicit
  wildcard support and multi-address host scope. Next automatic calendar version;
  no schema, permission or software-version-seed change.
- Summary: server Test sync was deleting browser-supported wildcard permits and
  rebuilding rules in global-list query order. Align supported rule semantics
  with the inspected browser mapper, suppress retained-rule duplicates, retain
  unchanged permit order and reject all-invalid replacements.

### Exact contract

- `POST /api/v1/sando/policies/preview`: unchanged bodyless, queryless API-key
  authentication with `state.read`, `sando.write`, `firewall.write`.
  Success remains `200`/`no-store`, full validated candidate and unchanged
  `base_revision`, `source_url`, `etag`, `imported_count`, `skipped_count`,
  `changed`, `config` fields/types. No apply/report/flag/status/cache writes.
- Automatic policy configuration remains full confirmed
  `POST /api/v1/transactions` / `POST /api/v1/transactions/{id}/confirm`,
  requiring `transactions.write`, `sando.write`, `firewall.write`.
  `GET /api/v1/sando` remains API-key/`state.read`, with existing policy
  counts/error/status fields and five-minute completion-relative polling.
- Previously server mapping skipped wildcard destination/port rows and hosts
  with multiple same-family addresses, duplicated retained matching permits,
  reordered all Sando permits and accepted all-invalid lists as deletions.
- Now explicit upstream `dst_ip:"*"` produces `0.0.0.0/0` or `::/0` in the
  source family; `dst_port:"*"` omits transport ports. ICMP/ICMPv6 accept
  integer/string zero or `"*"`. Transport zero, missing/null/invalid fields,
  wildcard sources, CIDRs and incompatible families remain unsupported.
- Source must match an existing configured host; the rule covers all that
  host's addresses in the matching family, as browser host rules do. Server
  policy sync/preview still do not import inventory or create new hosts.
- Duplicate comparison uses matching/action fields, not ownership/display
  metadata. Retained manual/other-provider rules prevent duplicate permits.
  Counts still separate unique Sando permits from skipped rows, not additions.
- Affected lists retain manual-first order, then other retained rules in
  relative order. Still-present Sando permits keep saved order and metadata;
  genuinely new permits append in source order. Pure source reordering returns
  `changed:false` after reconciliation and creates no automatic revision.
- `[]` still removes only Sando-owned host rules. A nonempty source with no
  supported existing-host rows now returns preview `422` with
  `{error,transaction:null}`; automatic sync reports an error, retains rules
  and does not advance its validator. Valid rows covered by retained rules
  are not an all-invalid failure. Other errors remain unchanged.

Synthetic upstream example:

```json
{"src_ip":"192.0.2.10","dst_ip":"*","protocol":"1","dst_port":"0"}
```

Generated host permit:

```json
{"origin":"import","import_source":"sando","destination":"0.0.0.0/0","protocol":"icmp","action":"accept"}
```

2. Update Test sync/automatic-policy help: explicit wildcard access is supported,

3. Render wildcard permits and partial skips clearly; show returned `422` errors

5. Deploy the fixed backend before enabling recurring policy sync. No migration,
