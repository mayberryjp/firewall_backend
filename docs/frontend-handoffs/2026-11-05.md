### Summary and methods

Build a two-firewall, deliberate start/cancel workflow for short-lived
authenticated packet-size/MSS measurements. Previously only passive link
diagnostics and timed DNS queries existed. Any suitable live IP-capable
interface can be selected; this is not VPN-only. The orchestrator temporarily
raises the selected interface to an explicit maximum, changes only explicitly
approved parents, and opens scoped expiring test permissions. It restores
owned originals afterward; no automatic persistent tuning or policy changes.

| Method/path | API-key grants | New behavior |
| --- | --- | --- |
| `POST /api/v1/diagnostics/path-tests` | `diagnostics.run`, `interfaces.write`, `firewall.write` together | Arm local test; accepted session `202` |
| `GET /api/v1/diagnostics/path-tests` | `state.read` | Current/last session, measurements and restoration status `200`; no body/query |
| `POST /api/v1/diagnostics/path-tests/{id}/cancel` | Same three start grants | Cancel and restore owned temporary state `200`; no body/query |

No separate `transactions.write` is needed for these operational actions.
No management API key is exchanged between firewalls. Register all methods in
the API client/Explorer, but do not emulate POST with GET or automatically run
start/cancel in bulk GET inspection, prefetch, polling or automatic retries.

### Request fields

Strict nonnull object; wrong JSON/types/nulls/unknown fields are `400`.
Synthetic example only, not a production pairing secret:

```json
{
  "interface": "vlan100",
  "source_address": "192.0.2.1",
  "peer_address": "192.0.2.2",
  "port": 49872,
  "maximum_mtu": 9000,
  "parents": [{"interface": "eno1", "maximum_mtu": 9100}],
  "pairing_secret": "synthetic-pairing-secret-1234567890"
}
```

- `interface:string`: valid live IP interface. Source must be assigned there;
  no automatic device/source/route fallback. Do not filter the selector to
  physical Ethernet/WireGuard or require a MAC address.
- `source_address:string`, `peer_address:string`: distinct same-family unicast
  IP literals, not hostnames, unspecified/multicast/loopback/limited broadcast.
  IPv6 link-local is unsupported; use unique-local or globally scoped addresses.
- `port:number`: integer 1024..65535, default 49872, UDP and TCP on that same
  number. Both sides must select the same reachable port.
- `maximum_mtu:number`: required integer 1280..65535 **bytes**, the temporary
  selected-interface ceiling, never lower than its current live MTU.
- `parents:{interface:string,maximum_mtu:number}[]`: default empty, maximum eight
  distinct explicitly approved ancestor interfaces, each maximum 1280..65535
  bytes and never lower than live MTU. Selected interface cannot repeat here.
  Preview affected interfaces/current MTUs and require explicit individual
  approval; do not silently select every uplink or guess a tunnel underlay.
- `pairing_secret:string`: write-only 32..128 non-space printable ASCII bytes
  (`!` through `~`). Generate
  at least 32 cryptographically random bytes in the browser, encode as hex and
  let the operator transfer it over a trusted channel. Submit over HTTPS or
  trusted management connectivity. Do not persist it in local/session storage,
  URL, drafts, saved configuration, logging, telemetry or history.

### Workflow, safety and errors

1. Select the local interface/source, peer IP, common port, maxima and approved
   parents on each firewall. Invert source/peer addresses at the other end.
2. Display a disruption warning: raising MTU can affect unrelated traffic and
   management on the selected interfaces. Submitting explicitly approves those
   temporary changes; no separate automatic-tuning toggle.
3. Use the same one-time secret and press Start on both ends within the
   30-second arming window. Timing is consent, not authentication.
4. Poll only the read-only status endpoint, without overlap. Show peer readiness,
   measurements, errors and cleanup/restoration state. Measurements have a
   30-second budget, within a 90-second overall session lifetime budget.
5. Keep cancellation available. Disable conflicting mutations until restoration
   releases the lease, including after a measurement failure. A cancellation
   response alone must not be interpreted as proof all cleanup has finished.
6. Render verified packet-size boundaries and measured TCP MSS evidence, not an
   absolute ideal MTU or automatic Apply. Any later saved MTU edit uses the
   normal reviewed confirmed configuration transaction.

Firewall permissions are exact peer/interface/test-port-scoped, not a blanket
allow or disable. Kernel leases expire even if the daemon dies; MTU restoration
after a killed daemon occurs when it restarts, not via a fictitious kernel MTU
timer. Incomplete restoration remains explicit and blocks mutations; do not
hide it as a completed/cancelled success. Do not broaden permissions to overcome
foreign policy or silently overwrite external interface changes.
Permit expiry/removal does not revoke already established conntrack
acceptance; unrelated connections are not flushed. Socket reservations remain
held after cleanup failure until successful recovery or process exit.
Startup refuses unresolved recovery rather than adopting foreign changes;
the status/cancel UI cannot operate while the daemon itself cannot start.

Preparation currently refuses any configured DHCP client, enabled BGP or
dynamic WireGuard DNS on the affected/unresolved tunnel path. Unrelated
dynamic tunnels do not block demonstrably nonencapsulating selected paths;
numeric-endpoint tunnels remain eligible. These are explicit `503` refusals;
do not disable live services automatically to bypass them. IPv6 tests require
committed IPv6 enablement. Both test source ports must be free before any
temporary mutation.

Known error handling: invalid values `422`; authentication `401`/`403`;
active transaction/test/restoration/maintenance `409`; bad ID/body/query `400`;
unknown cancellation ID `404`; unsupported method `405`; unsupported backend or
native preparation/control failure `503`. The simulator never claims measured
success. GET status can remain `200` with an explicitly failed session/result.

### Rendering, deployment and acceptance

- Implement the exact [status/progress and measurement schemas](../../FRONTEND_SPEC.md#status-and-progress).
  Outer `state:"running"` includes nested armed/paired progress. Gate writes on
  `active:false`, not just completed measurement results. Render
  `restoration`, observed/identity-checked MTU rows, error and warnings.
  Use the native 32-hex `id` for cancellation, not result `session_id`.
- Firewall-counter and observe/repair reads can be temporarily unavailable
  while temporary rules are owned. Keep dedicated status polling available;
  do not replace unavailable data with zero or discard saved rules.
- Preserve byte units: total IP packet size is not TCP MSS. Show requested
  versus observed MSS, delivered/sent/loss, timings, goodput and retransmission
  evidence where available, with null/unavailable distinct from zero.
- Separate inbound/outbound results and local/interface/peer/route caps from
  verified path evidence. Timeouts/loss are not proof a size is too large.
  Inner delivery is not proof of no outer tunnel fragmentation.
- Brief tests, CPU load/congestion, asymmetric paths, ECMP and route changes
  limit conclusions. Require direct peer reachability; do not promise NAT
  traversal or create persistent forwarding rules.
- These are endpoint tests, not proof of forwarded-LAN throughput. Per-socket
  MSS trials do not implement persistent TCP MSS clamping; do not add an
  automatic "Apply MSS" action.
- Render finite candidate sampling (up to 12 IP sizes and three MSS trials per
  direction), not a byte-exact MTU search. TCP trials are capped at 4 MiB each
  and approximately 8 MiB/s. `limits.path_mtu_bytes` is deliberately null.
  Missing authenticated peer reports leave sender evidence null/unavailable,
  not zero. Neither best observed goodput nor an ACK timeout proves an ideal MTU.
  Show outbound trial `error` reasons for inconclusive measurements; do not
  turn null evidence into zero throughput.
- Deploy the backend before enabling the UI. Operators need the native Linux
  backend, interface/route privileges, supported MTU ceilings, packet-size
  socket controls and working nftables lease support. No iperf or supervised
  external network service is installed.
- Acceptance must cover simultaneous starts and late/missing/mismatched peer,
  exact source/interface binding, physical/VLAN/tunnel targets and approved
  parent changes, bidirectional sizes/MSS, cancellation/deadline/failure,
  state/secret isolation, expiry, daemon restart and original restoration,
  foreign replacement, insufficient grants and blocked conflicting writes.
  Frontend/browser and appliance performance acceptance remain unverified
  until executed; consult the journal for backend tests actually run.
