Status follows applied/provisional configuration, which can differ from the
committed read or an editor draft.

### New mDNS filter counter shape

Previously mDNS exposed only service-wide counters. It now always includes
`filter_counters`, one row per applied `mdns.reflection.filters` entry in
applied order. Synthetic status fragment:

```json
{
  "name": "mdns",
  "state": "running",
  "reflection_enabled": true,
  "filter_counters": [
    {
      "filter": "_ipp._tcp.local.",
      "matched_packets": "42",
      "transmitted_packets": "84",
      "last_used_at": "2026-11-01T23:20:00Z",
      "last_transmitted_at": "2026-11-01T23:20:00Z"
    }
  ]
}
```

- `filter`: canonical applied DNS selector string; join by this value, not
  index. Supports service types, subtypes, exact instances and providers.
- `matched_packets`, `transmitted_packets`: non-null saturating unsigned
  64-bit decimal strings. Never convert to JavaScript `number`; use strings
  for display or `BigInt` for comparison/deltas.
- Matched counts each admitted ingress datagram once per contributing entry,
  across permitted questions/all RR sections and learned dependencies. It is
  sampled after filtering, before later returned-packet/egress suppression.
  Provider/instance browse solicitation and enumeration are matches, not
  evidence of an actual matching device.
- Forwarded counts successful reflected destination sends, including legacy
  unicast replies and each split fragment only for entries present in it.
  Failed/rate-limited sends and appliance publishing do not increment it.
  Sending is not proof of remote receipt.
- Overlap can credit multiple filters for the same packet; entry totals must
  not be summed to derive the global total. Counts cover both families and
  all selected interfaces, not a directional traffic breakdown.
- `last_used_at`, `last_transmitted_at`: UTC RFC3339 string or null before a
  match/successful send. Both reset with counts to `"0"`/null on each worker
  run (retry, restart, replacement/rollback). No history persistence.
- Empty filters yield `[]`, including unfiltered reflection. Configured filters
  remain present with zero/null values when mDNS/reflection is disabled.
  Simulator zeroes are unmeasured, not verified inactivity. Use lifecycle
  `state`, `started_at`, `restart_count`, sample `collected_at`, errors/warnings
  and `statistics_complete` to explain resets and measurement limitations.

### Existing UDP per-instance counter shape

Synthetic counter-bearing fragment of a `UDPRelayStatus` row (other existing
configuration, lifecycle and limits fields are omitted here):

```json
{
  "name": "udp-broadcast-relay",
  "instance_id": 1,
  "state": "running",
  "received_packets": "42",
  "transmitted_packets": "84",
  "received_bytes": "4200",
  "transmitted_bytes": "8400",
  "policy_drops": "0",
  "loop_drops": "0",
  "rate_limit_drops": "0",
  "send_errors": "0",
  "last_send_error": null,
  "last_send_error_at": null,
  "receive_drops": null,
  "statistics_complete": false,
  "collected_at": "2026-11-01T23:20:00Z"
}
```

All eight counters are non-null saturating `u64` decimal strings:
`received_packets`, `transmitted_packets`, `received_bytes`,
`transmitted_bytes`, `policy_drops`, `loop_drops`, `rate_limit_drops`,
`send_errors`. Packet counts distinguish receives from successful per-egress
sends; one receive can produce multiple forwards. Bytes are UDP payload only,
not IP/Ethernet overhead. Counters reset per socket attempt, not persisted.

Join numeric `instance_id` (1..63) to configuration `instances[].id`; shared
`name` is not unique. `last_send_error` is string/null,
`last_send_error_at` UTC timestamp/null. `receive_drops` is string/null but the
current relay always reports null for unknown kernel receive loss;
`statistics_complete:false` alone is not a health alert or a zero-loss claim.
There is **no UDP last-used timestamp**. `collected_at` is sample time, not
the last receive/send time. Retain normal current/retained errors, retry and
restart indicators. Disabled/simulated values are not measured live traffic.

### Concrete frontend tasks and coordination

1. Add `MDNSFilterCounters` and mandatory `MDNSStatus.filter_counters` to
   specialized/heterogeneous runtime decoding. Keep the distinct existing
   `UDPRelayStatus` shape; do not decode relay rows as mDNS/generic samples.
2. Show Matched / Forwarded / Last used per canonical mDNS filter. Optionally
   show Last forwarded for diagnosing matches with unsuccessful sends.
   Show Received / Forwarded per UDP instance and optional bytes/drop/errors.
3. Poll existing status endpoints single-flight every 2..5 seconds while
   visible. Do not overwrite drafts or attribute provisional rows to renamed
   committed/draft entries; distinguish applied/committed membership.
4. Render never-used null timestamps, disabled/reflection-off, simulated,
   stopped/error/retrying, unknown-loss and no-filter states honestly.
   Zero means no observations in the current worker run, not lifetime non-use.
5. Deploy the backend containing these additive fields with the updated strict
   client contract; no saved-state changes, migration or compatibility window.
   Existing multicast membership, LAN eligibility, UDP/5353 host input and
   separate routed application access prerequisites remain unchanged.

### Acceptance and validation

- Allowed query/response increments the selected mDNS entry, not an unrelated
  entry. A query-only match must not claim a discovered device.
- Overlapping service/instance/provider filters can share credit; learned
  address dependencies expire and goodbyes are attributed before cleanup.
- Multi-destination and split-message sends count actual attributed fragments;
  failures/rate drops and appliance publication never inflate forwards.
- Restart/retry/config replacement reset counters/timestamps without changing
  configuration revisions; rollback restores configured filter identities.
- Decimal values above JavaScript's safe integer range display exactly.
  Empty filters and disabled/simulated/error states decode and render.
- UDP joins by ID, renders all eight fields exactly and does not label
  collection time as Last used or unknown kernel loss as a health alarm.
- Backend checks: focused core/service mDNS tests and all eight isolated native
  mDNS fixtures passed. Final workspace checks are recorded in the
  [journal](../journal/2026-11-01.md). Frontend/browser and real appliance/device
  integration remain pending; this repository does not implement that client.
