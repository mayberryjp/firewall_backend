  deployment/live Sando acceptance remains pending.
- Keep separate **Force host sync** and **Force policy sync** buttons, without
  browser imports or Test sync. Both work with automation disabled and leave
  sync flags and browser import reports unchanged.
- Bodyless/queryless `POST /api/v1/sando/hosts/sync` and
  `POST /api/v1/sando/policies/sync`, requiring API-key `state.read`,
  `sando.write`, `firewall.write`, `transactions.write`.
- `200`/`no-store` returns the full `GET /sando` status shape, with separate
  updated server success timestamps. Fetch/apply/verification/confirmation run
  on the daemon, using committed endpoint and existing reconciliation rules.
  Policy requests ignore ETags and fetch the complete list.
- Errors: `401`/`403` auth/permission, `405` method, `400` body/query,
  `422` missing saved endpoint, `409` active sync or configuration busy before
  acquisition, `503` acquisition/validation/apply/cache/unavailable or revision
  changed during acquisition. No automatic POST retries.
- Disable actions during initial/stale reads, conflicting operations and dirty
  drafts. Preserve drafts and show save/discard guidance inline. On success,
  refresh committed configuration and timestamps. No new warning popups.

### Exact contract and frontend actions

- `GET /api/v1/sando`: API key, `state.read`, no query/body, `200`/`no-store`.
  New top-level `removed_hosts: number` is a non-null integer host count for the
  latest successful host reconciliation, initially zero; runtime/current-source
  scoped, reset on restart/source change, retained after failure/while disabled.
  `last_changed_revision: string|null` now covers additions **or deletions**.
  Existing last attempt/success/error fields cover completed automatic sync.
  Display separate host and policy success times using `last_success_at` and
  `policies.last_success_at`, not saved browser import reports.
- Config/revision/state/transaction host objects add `origin:"manual"|"import"`
  and `sando_source?: string|null`. The daemon serializes origin always; absent/
  null source means none. New human input defaults to manual. Automatic hosts
  receive import origin and the committed source URL. Imported requires source;
  manual excludes source. URL uses existing Sando absolute HTTP(S), credential-
  free, no query/fragment/port-zero, 1..2048-byte validation.
- `POST /api/v1/transactions` retains full-config/base revision and API-key
  `transactions.write` plus affected domain permissions. Preserve both fields
  exactly on retained hosts; client-created hosts must be manual with no source.
  Attempted ownership forgery/change/clearing returns `422` with the normal
  `{error,transaction}` envelope. Confirm/rollback endpoints and permissions
  remain unchanged; restore preserves saved provenance.
- Update client types, cloning/serialization, draft/rebase handling and host
  displays. Ownership is read-only, not a toggle users can edit.
- Automatic host sync removes missing **same-source imported** hosts and their
  default policy/all host rules, **including manual rules on those hosts**.
  Any saved IPv4/IPv6 address seen in a validated nonempty snapshot keeps the
  host. Manual/unmarked and other-source hosts are preserved. No name/ID/history
  inference, migration or compatibility path. Existing unmarked hosts are not
  auto-tagged; do not invent client-side attribution.
- Empty/addressless inventory previously succeeded and cleared metadata; now
  status becomes `error`, retaining configuration/last successful metadata/time.
  Fetch/JSON/busy/apply/validation failures do not delete hosts.
- Surviving rules referencing removed hosts block the entire reconciliation;
  display the explicit error and direct the operator to resolve those references
  through a reviewed transaction. Do not remove unrelated rules automatically.
- Add deletion counts, warnings about manual rules on imported hosts, and
  refresh committed host/rule inventory on automatic revision notifications.
  Preserve unsaved drafts and use normal stale-base conflict handling.
