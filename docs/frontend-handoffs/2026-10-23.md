### Contract

Previously a new native journal was empty, roles were WAN/LAN only, and no DHCP
client or resolver maps existed. First supported host startup now imports
physical NICs into a virgin journal with `unassigned` roles and takes exclusive
per-NIC IP/DHCP ownership from networkd. Configured/history-bearing journals are
not recaptured. A completed native receipt without its core journal now fails
explicitly rather than reconstructing stale configuration. No WAN guessing,
API-key/authentication or onboarding change.

Exact affected HTTP surfaces, unchanged methods/paths:

- `GET /api/v1/state`: embedded configurations contain optional `dhcp_clients`
  and `dns`; revision zero can already have managed NICs.
- `GET /api/v1/interfaces`, `GET /api/v1/interfaces/{name}`: role accepts
  `unassigned`; addresses remain verified static configuration, not DHCP leases.
- `GET /api/v1/interfaces/discovered`: unchanged read-only live inventory.
- `GET /api/v1/runtime`: native `dhcp_clients: { leases, errors }`; live lease
  address/server, finite Unix-second times, routes, DNS/domain and nullable MTU.
- `GET /api/v1/transactions`, `GET /api/v1/transactions/{id}`,
  `GET /api/v1/revisions`, `GET /api/v1/revisions/{revision}`: embedded Config
  values preserve the maps and role, including frontend exports of those values.
- `POST /api/v1/transactions`, `POST /api/v1/revisions/{revision}/restore`:
  Config values include the maps. Confirmation/rollback and provisional/deadline
  handling do not change; dropping a map is a real configuration removal.
- Existing `POST /api/v1/services/{softflowd,dhcp-relay,gateway-monitoring,ntp,syslog,vnstat}/reconcile`
  additionally require `interfaces.write` when clients or DNS maps are
  configured, as well as existing selected/enabled-service permissions.

Reads retain API-key `state.read`; map changes use `interfaces.write` and normal
transaction authorization. Unknown/null fields are 400; invalid schema values
422; missing permissions 403; conflict 409 and existing transaction apply/recovery
and observation 503 handling remain. No new dedicated DHCP/DNS endpoints.

Synthetic Config fragment (not a complete transaction body):

```json
{
  "dhcp_clients": {
    "enp1s0": {
      "client_id": "01525400123456",
      "hostname": "appliance",
      "route_metric": 100,
      "use_mtu": false,
      "use_domains": "no"
    }
  },
  "dns": {
    "enp1s0": {
      "servers": ["192.0.2.53"],
      "domains": [{ "name": "example.test", "route_only": true }]
    }
  }
}
```

Canonical fields/defaults/limits: [spec](../../FRONTEND_SPEC.md#dhcpv4-and-resolver-configuration).
Maps default empty and may be omitted when empty; explicit null is invalid.
DHCP defaults are empty ID/hostname, metric 0, MTU false, domains `no`.
Client ID is 2..255 hex-decoded bytes or empty; hostname max 253; metric uint32.
DHCP requires Ethernet, no enabled relay and no static IPv4 on that NIC.
Static IPv6 may coexist. DNS allows 8 unique literal servers and 32 unique
domains per configured interface; domain `name` and `route_only` are required.
Dynamic MTU is nullable and, when applied, 1280..65535 bytes. Lease timestamps
are Unix seconds; lease/renew/rebind fields are seconds, not milliseconds.
Native leases are absent until obtained; simulator does not invent leases.

### Frontend Tasks

1. Update Config/role/runtime types and all round-trip/export/restore paths.
   Preserve maps on unrelated edits and handle empty-map omission.
2. Add Unassigned without guessing WAN/LAN; accept populated revision-zero
   baselines. Earlier role-only handoffs are superseded on this enum detail.
3. Add static/DHCP mode, ID/hostname/metric, DHCP MTU/domain and resolver controls.
   Enforce relay/static-IPv4 exclusivity and current numeric/domain limits.
4. Render dynamic leases/routes/resolver data separately from editable static
   state. Calculate expiry from Unix seconds, show unavailable/errors, and retain
   existing polling, independent connectivity verification and explicit confirm.
5. Update scoped-key repair messaging for the additional interface permission.
   Explain that stopping/removing Netcontrol configuration does not restart OS
   DHCP or remove its persistent networkd exclusions.

### Deployment and Acceptance

Deploy frontend/backend together for the changed Config and role contract, with
no compatibility window or state reset. First native host start needs root,
stable/private persistent state, networkd/resolved and active finite DHCPv4
leases. NetworkManager, active dynamic global IPv6, bridged/bonded ports, custom
policy rules and unsupported manager options fail explicitly. Wi-Fi association
remains with the existing supplicant; DHCP/IP is Netcontrol-owned. Keep console
access; automatic first-start handover can affect management reachability.

Required operator checks: Ubuntu build; static/DHCP first start; client identity,
route metric, DNS and connectivity preservation; renewal/rebind/NAK/expiry;
restart/reboot; provisional apply/rollback; interrupted adoption/lease update;
foreign-route/drift rejection; repeated start without recapture; scoped repair
403 and schema 400/422. No first-party test code added or tests run per user
direction. Local syntax checks passed; portable compile attempt was blocked by
missing Windows MSVC linker and does not validate Linux native code.
