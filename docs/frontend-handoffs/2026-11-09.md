## 2026-11-09-01 Install and source-upgrade MOTD cleanup

- **Summary:** installation and full source upgrades now remove Ubuntu MOTD output.
- **Priority:** medium.
- **Classification:** required operator-help update; no API client or UI form work.
- **Status:** Pending frontend review.
- **Backend availability:** Unreleased working tree; not committed, published or deployed.
- **Contract/recommended bump:** breaking deployment policy; next automatic calendar version.

### Contract and frontend tasks

Previously the scripts left MOTD services, PAM output, files and generators alone.
Now both scripts stop/disable and persistently mask standard MOTD units, remove
active `pam_motd.so` lines from regular PAM configuration files and delete the
standard content/generator/cache paths listed in the
[installation guide](../BUILD_AND_INSTALL.md#motd-cleanup). Absent units are also
masked. Targeted custom MOTD content is deleted; packages/distribution unit
definitions are not purged. Other authentication/session modules, credentials,
firewall state, `/etc/issue`, SSH `Banner` settings and embedded SSH greetings
remain unchanged.

**Affected HTTP methods/paths: none.** In particular, `POST /api/v1/system/upgrade`
and automatic HTTPS self-upgrades do not run this cleanup. Request/response
fields, types, nullability, defaults, units, limits, HTTP status/error behavior,
authentication and permissions are unchanged; there is no new JSON payload.

Update install/full source-upgrade operator instructions to disclose deleted
custom MOTD content and suggest saving wanted banners separately beforehand.
Distinguish full deployment from `upgrade.sh --build-only`, HTTP/automatic
self-upgrades, signed-package installs and standalone hardening/reset, which
do not add this policy. No client types, forms, rendering, polling or state
handling changes are needed.

### Deployment and acceptance

Requires the existing root/sudo Ubuntu/systemd deployment prerequisites. Cleanup
occurs before provisioning/binary replacement and aborts deployment on inspection,
unit-control, PAM-write or removal failures. Changes already made to the host
are not undone by binary rollback. Unsafe parent symlinks and non-regular/symlink
PAM files are errors; leaf MOTD symlink targets are preserved. Later package or
operator changes can recreate files/PAM lines; the next full script run cleans
them again. No API deployment ordering or compatibility window is required.

Acceptance: fresh install/full source upgrade leaves listed units stopped and
persistently masked, removes listed paths and active PAM MOTD entries, retains
unrelated login modules/banners and allows normal OS login without MOTD. Repeat
cleanup succeeds; failures prevent deployment. Confirm excluded upgrade paths
do not promise this policy.

Backend validation: Bash syntax checks and the full mocked installer regression
suite passed in an isolated network-disabled Linux container, including MOTD
removal/repeat cleanup, service-state failures, symlink safety, PAM mode/content
preservation, deployment ordering and binary recovery. Actual Ubuntu/systemd,
OS SSH/console login and package-reinstall acceptance are not run.

- Classification: **optional**; priority normal.
- Status: **Pending frontend review**. Not sent or acknowledged.
- Backend availability: **Unreleased**.
- Contract impact/recommended bump: additive notification metadata; next
  automatic calendar version. No HTTP or persisted-schema changes.

### Behavior and affected surfaces

Previously Discord endpoints displayed only IPs/ports and used the firewall's
hostname in the title. Now the embed title is `New firewall drop` and its author
is `system.hostname` plus `.` plus `system.domain` when both are configured.

Exact IP matches in committed `firewall.policies.hosts` take precedence over
cached Sando host names. Sando cache must match current `sando.api_url`; retained
names remain usable with sync disabled or a failed refresh. Unknown endpoints
retain IP/port only. No live lookup, subnet guessing or new identity inference.
Long names split messages within ten embeds/6000 total embed characters;
mentions remain disabled. Deduplication, notification flags and best-effort
delivery semantics are unchanged. Configuration is checked before each split
message and during delivery/retry; interrupted claimed entries are not replayed.

No affected HTTP methods/paths, authentication, permissions, request/response
fields, validation, status codes or errors change. Existing configuration
transactions, `GET /api/v1/sando`, webhook upload and Discord status remain as
documented. No new form/client types or polling are required.

remain; Sando fallback requires an available matching cache.

### Acceptance and evidence

Verify named IPv4/IPv6 endpoints, configured-name precedence, unnamed endpoints,

## 2026-11-09-04 Server-side drop category filtering

- **Summary:** request whether to include broadcast and TCP FIN/RST/ACK-only
  drops; both categories are excluded by default.
- **Priority:** high.
- **Classification:** required client/query controls and paging behavior.
- **Status:** Pending frontend review; not sent or acknowledged.
- **Backend availability:** Unreleased working tree; no approved release/commit.
- **Contract/recommended bump:** breaking retrieval-default change with additive
  queries; next automatic calendar version.
- **Supersedes:** frontend-only category filtering in
  [2026-11-08-05](2026-11-08.md#2026-11-08-05-frontend-only-drop-tag-filtering)
  and earlier default-all/local-hide instructions in item 04 of that day.

### Exact HTTP contract

`GET /api/v1/firewall/deny-log`, API key and `firewall.logs.read` only:
no body, no-store. Previously pages included all tags and category filtering
was local. Now two optional query fields select categories before pagination:

| Query field | Type/default | Meaning |
| --- | --- | --- |
| `include_broadcast` | nonnull boolean string, `false` | `true` allows saved `ipv4_broadcast` records |
| `include_tcp_closures` | nonnull boolean string, `false` | `true` allows saved `tcp_finish`, `tcp_reset` and `tcp_ack_only` records |

Accept exactly lowercase `true`/`false`. Omission means false, not null.
Reject empty values, numeric booleans, uppercase, whitespace, duplicate keys and
unknown queries with `400`; `tag` and `exclude_tags` remain unsupported.
No new request-body/configuration fields or response fields. Limits remain
`limit` 1..500, default 100, and total query <=4096 bytes. Existing
`before_id`, `since_ms`, `until_ms`, `address`, `protocol` and `chain` are unchanged
and combine with the category restrictions using AND.

True includes a category alongside ordinary drops, not a category-only view.
An overlapping broadcast/FIN/RST/ACK-only record requires both flags true.
Only stored tags decide inclusion. Unknown TCP flags, unknown ACK payload length
and nonempty ACK payload are not treated as empty ACK-only traffic. SYN-only
and otherwise untagged records remain eligible by default.

Examples:

```text
GET /api/v1/firewall/deny-log?limit=100
GET /api/v1/firewall/deny-log?limit=100&include_broadcast=true
GET /api/v1/firewall/deny-log?limit=100&include_tcp_closures=true
GET /api/v1/firewall/deny-log?limit=100&include_broadcast=true&include_tcp_closures=true
```

The last request includes all categories within other selection/retention limits.
Successful `200` shape is unchanged. Synthetic partial response example:

```json
{"records":[],"next_before_id":null,"oldest_id":"1","newest_id":"42","cursor_expired":false}
```

This can mean retained history contains only excluded categories, not no capture.
`next_before_id:string|null` refers to another matching page after filtering;
`oldest_id`/`newest_id:string|null` remain global retained boundaries.
`cursor_expired:boolean`, retention/capture fields and record metadata
nullability/units are unchanged. HTTP errors remain `401`/`403` for credentials/
permissions, `405` for other methods, `400` for invalid query/body and `503` for
unavailable backend; use the existing `{error, transaction}` envelope.

### Frontend tasks and deployment

- Add request/client types for both flags and initially-off Include IPv4
  broadcast and Include TCP FIN/RST/ACK-only controls. Explain that ACK-only
  is observed empty payload, not proof of teardown.
- Replace local category hiding with server-side query construction. Omit a
  false flag or send `false`; send `true` only when the user enables inclusion.
- On any selection change, clear the selected history pages/cursor and refetch
  the newest page. Cancel or ignore late responses from the previous selection.
- Keep the flags and other filters identical on every cursor request. Use the
  actual `next_before_id`; do not derive a cursor from visible/global boundary IDs.
- Render no retained matching drops separately from no history, and preserve
  capture/error/loss/retention-gap notices. Do not use global IDs as match counts.

Coordinate new query controls with the accepting backend; existing frontends
without flags now receive the excluded-default view. No compatibility aliases,
schema conversion, state reset or new Linux operator prerequisite. Capture,
retention, firewall verdicts, Discord flags/deduplication/delivery and worker
lifecycle are unchanged. Request flags never mutate notification configuration.

### Acceptance and validation

Verify the default excludes FIN, RST, empty ACK-only and IPv4 broadcast; enable
each flag independently, then both, including overlapping records. Keep SYN,
untagged, unknown flags and unknown/nonempty ACK payload eligible. Combine with
address/protocol/chain/time selection; reject malformed/duplicate booleans.
Check filtered full-page limits, gaps between matching IDs, last matching cursor
null despite older excluded rows, global boundaries, refresh/selection races,
capture errors and retention notices.

- Targeted deny-log tests: **19 passed, 1 privileged test ignored, 0 failed**.
- Full workspace tests: **670 passed, 96 ignored, 0 failed**.
- Workspace strict Clippy, format check, build and whitespace check: **passed**.
- Cached stable Rust, committed lockfile and offline dependencies in a
  network-disabled Linux container; no dependency installation.
- Privileged NFLOG/namespace and deployed frontend/appliance integration:
  **not run**. Tests establish query/storage/paging behavior, not live capture

## 2026-11-09-06 Exclusive OS NTP ownership

- **Summary:** install/full source upgrade disables competing OS time clients.
- **Priority:** high; **classification:** required NTP/operator-help update.
- **Status:** Pending frontend review; not sent or acknowledged.
- **Backend availability:** Unreleased working tree; not deployed or published.
- **Contract/recommended bump:** fix with breaking deployment policy; next
  automatic calendar version.

### Previous versus new behavior

Previously the scripts enabled host-service availability without disabling OS NTP.
Now they stop/disable and persistently mask timesyncd, chrony/chronyd,
ntp/ntpd/ntpsec/openntpd/busybox-ntpd and one-shot ntpdate/sntp/ntpdig units/timers.
Absent unit names are masked too. Verify inactive/failed state and persistent
masks, then reject remaining known clients, including truncated timesyncd names.
Inspection/control/verification errors abort before provisioning or replacement;
already-applied masks are not undone by binary rollback. Custom unmanaged
clients/cron launchers must be disabled independently; no arbitrary process killing
or outbound/forwarded UDP/123 policy change.

Saved `ntp.enabled:boolean` (default false) and `ntp.servers:string[]` are unchanged.
The existing 0..8 unique host/IP limit and enabling requirement of at least one
server remain. Disabled no longer leaves standard OS clients available for clock
sync; enabled queries only configured servers without implicit public fallback.
Disabling Netcontrol NTP does not restore OS clients. Clock discipline remains
client-only/slew-only; running is not synchronization.

**Changed HTTP methods/paths: none.** `GET /api/v1/services/ntp`,
`GET /api/v1/services/ntp/status`, `POST /api/v1/services/ntp/reconcile` and existing
configuration transactions retain request/response fields, types, nullability,
units, defaults, validation, status/errors, authentication and permissions.
Existing reads require `state.read`; NTP changes use `ntp.write` and the existing
transaction permissions. No new JSON request or response is introduced.

### Required frontend tasks and deployment

Update NTP settings help and install/full-upgrade instructions: explicitly
configure the desired servers and enable NTP to maintain appliance clock time.
Explain disabled means no managed time synchronization and drift can affect TLS
and other time-sensitive operations. Do not claim OS fallback or synchronized
time from a running worker. No client types/forms/polling/state changes needed.

Existing appliances must run the revised full source upgrade to install masks.
Build-only, HTTP/automatic HTTPS binary self-upgrades, signed packages,
manual/OpenRC deployments and standalone hardening/reset do not establish this
systemd policy; binary updates retain masks already installed. Root/sudo,
running Ubuntu/systemd and `procps` are required. No API deployment coordination,
state migration or compatibility window.

### Acceptance and validation

Confirm install/full upgrade stops and persistently masks every listed unit,
including absent/already-masked units; repeat and reboot retain ownership.
Control/readback/residual-process errors must prevent deployment. Configure an
intended server and verify host-originated UDP/123 only reaches its resolved
endpoint; disable NTP and verify managed queries stop without restarting OS
clients. Separate forwarded LAN traffic from host queries and inspect custom
launchers independently.

Bash syntax and the full mocked installer suite passed in an isolated,
network-disabled Linux container, covering NTP units/process failures, masks,
repeat/absent cases, deployment ordering and existing binary recovery.
Actual Ubuntu/systemd/reboot, clock behavior and packet capture are not run;
no production deployment or frontend integration is claimed.
