# Frontend Handoffs - 2026-10-28

## 2026-10-28-01 Managed restart and timed DNS actions

- Priority: normal. Classification: **required**. Status: **Pending frontend
  review**. Backend availability: **Unreleased**, not deployed or delivered.
  Recommended bump: minor for additive operational APIs/permissions and manager
  health entries; baseline unknown. No persisted configuration schema change.
- Previously there was no targeted managed-worker/daemon restart or timed DNS
  lookup action. New API-key-authenticated actions:
  - `POST /api/v1/processes/restart`, permission `system.restart`.
  - `POST /api/v1/diagnostics/dns-lookup`, permission `diagnostics.run`.
  Neither requires `transactions.write` or `state.read`, creates a revision or
  performs broad network repair. Device keys receive the permissions; scoped
  credential files need explicit grants. Existing read permissions still apply
  when subsequently polling status.
- Both require strict JSON, no query parameters; normal `401`/`403`, `405` for
  other methods, `400` for invalid payload/query, `409` during active transaction,
  recovery, upgrade or daemon restart, `503` for unavailable preparation/backend.
  Use the full
  [canonical contract](../../FRONTEND_SPEC.md#operational-restart-and-dns-diagnostics)
  for exact supported target IDs and all response fields/limits.

### Restart UI and client work

- Add a deliberate confirmation action on managed process/status views.
  Synthetic request: `{"target":"ntp"}`. This is not arbitrary PID/process
  killing. Native targets must be configured/enabled: unknown returns `404`,
  disabled returns `409`, unavailable returns `503`.
- Native completion is `200 {target,status:"restarted",worker:<status>}`;
  simulator is `status:"simulated"`. Completion does not promise protocol
  health, a new DHCP lease, synchronization or upstream delivery.
- Async manager example:
  `{"target":"mqtt","status":"restart_requested","generation":1}`, HTTP `202`.
  Generation is ephemeral, not a revision or completion token; requests during
  drain can coalesce. Poll existing status, do not automatically repeat.
- Daemon request: `{"target":"netcontrold"}`; `202` acknowledges graceful
  scheduling. It drains HTTP/SSH/workers and durably shuts down, then relies on
  the packaged native host-mode systemd/watchdog on-failure restart policy.
  Manual/simulator/OpenRC/namespace launches return `503`. No new installer
  prerequisites beyond that existing service policy are introduced.
- Warn about temporary management loss, DHCP connectivity effects, selected
  worker cache/counter resets and possible syslog delivery gaps. Preserve drafts,
  handle unknown outcomes without blindly resubmitting, and reconnect with
  bounded backoff. Persistent accounting databases/configuration remain intact.
- Existing platform/process-health/MQTT components gain `managed_processes`
  resources for the async runners. Accept `running`, `restarting`, `error`,
  `stopped`; errors remain visible while their controller accepts a new restart.
  Do not turn a service failure into a global draft/editing lock.

### DNS diagnostic UI and client work

- Provide required interface selection and hostname, A/AAAA selection, optional
  timeout. Synthetic request:
  ```json
  {"interface":"wan0","hostname":"example.test","record_type":"A","timeout_ms":2000}
  ```
- `record_type` defaults to A, only A/AAAA. `timeout_ms` is an integer 100..5000,
  default 2000. Hostname is ASCII, labels 1..63, total <=253 excluding optional
  final dot, alphanumeric ends and alphanumeric/hyphen interiors; no IP literals.
  Returned hostname is lowercase without final dot. No resolver override input.
- Selects that up configured interface's configured then valid matching DHCP
  servers, respecting DNS override and global IPv6 resolver policy. No public
  fallback or OS hosts/cache lookup; the queried resolver may cache.
- Render `status`, addresses, DNS `rcode`, chosen server/transport,
  numeric millisecond `rtt_ms`/`elapsed_ms`, attempts, opaque scope and captured
  revision. Null RTT is unavailable, not zero. RTT includes server processing;
  TCP fallback RTT excludes connect/earlier UDP, while elapsed includes them.
- First valid DNS response ends lookup, including NXDOMAIN/SERVFAIL/REFUSED;
  nonzero codes have empty answers but measured RTT. Only transport/protocol
  failures advance to the next server. All failed attempts are HTTP `200` with
  `status:"failed"`, null answer timing/server/transport/code, empty addresses,
  and explicit attempt errors. Simulator is `simulated` with null timing.
- Single-flight the form; do not continuously poll the lookup. Backend permits
  two concurrent operations; additional requests return `429`. DNS network I/O
  does not hold the engine lock or stop concurrent configuration workflows.
