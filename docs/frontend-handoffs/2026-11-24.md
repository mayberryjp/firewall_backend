## 2026-11-24-01 Test sync staged policy preview

- Priority: high. Classification: **required**. Status: **Pending frontend review**.
- Backend availability: unreleased working-tree changes; no commit, release,
  deployment, push or frontend delivery claimed.
- Contract impact: additive preview-only endpoint, no persisted schema changes.
  Recommended bump: next automatic calendar software version; seed unchanged.
- Summary: add a **Test sync** button to Settings > Sando which retrieves/maps
  policies server-side once and stages the result in existing **Save / Commit**.
  Unlike recurring policy sync, retrieval does not apply rules or enable polling.

### Endpoint and response

`POST /api/v1/sando/policies/preview`, API-key authenticated, requires
`state.read`, `sando.write`, `firewall.write`. No query/body, including no `{}`.
Preview does not require `transactions.write`; subsequent saves/confirmation
retain normal transaction and affected-component permissions.

Previously there was no backend one-time preview; browser imports mapped their
own responses and automatic sync directly applied its mapped result. The new
endpoint returns `200`/`no-store`, no Location header or transaction:

```ts
interface SandoPolicyPreview {
  base_revision: string;
  source_url: string;
  etag: string;
  imported_count: number;
  skipped_count: number;
  changed: boolean;
  config: Config;
}
```

All fields are non-null. Revision is canonical `yyyy.mm.dd.iteration`; source is
the committed absolute Sando base URL, ETag an opaque string. Counts are integer
row-mapping totals, not added/deleted-rule counts; `changed` compares proposed
firewall configuration to the committed firewall. `config` is the complete
validated candidate, including unchanged read-only software metadata.

The daemon unconditionally fetches `<saved api_url>/api/ignorelist` with existing
proxy-prefix, no-redirect/no-proxy, five-second connect/thirty-second request,
4 MiB body, 4096 row and 512-byte ETag restrictions. No API key is forwarded.
Same exact-source-host/protocol/port mapping and Sando-owned host-rule replacement
as automatic sync. Empty/all-skipped lists may propose deleting old Sando host
rules, never manual/other-provider rules, host defaults/inventory, interface
rules, input or NAT. No reports, worker status/cache/ETag or sync flags are written.

Errors use `{error,transaction:null}`:

- `401` authentication; `403` missing preview authority.
- `400` body/query; `405` wrong method.
- `422` saved URL absent or invalid mapped configuration.
- `409` busy configuration or revision/source changes during retrieval.
- `429` another preview running (single preview slot).
- `503` unavailable manager/engine/upgrade state or upstream transport/HTTP/
  JSON/ETag/body/row-limit failure.

### Required frontend tasks

1. Add the button/client response type. Require saved URL and all preview
   permissions. Neither sync toggle needs enabling.
2. Require a clean existing draft. Preserve dirty edits and explain that the
   user must save/discard them before testing; never silently overwrite them.
3. Disable duplicate clicks while fetching. Send no body. On error preserve
   the draft and show the returned error. Retry stale previews against current
   state, not by retaining an obsolete full candidate.
4. On success verify the committed revision equals `base_revision` and that
   the draft remained clean during retrieval. Stage `config` with that revision
   and navigate to **Save / Commit**. Render the semantic diff, source,
   imported/skipped counts and removed/new rules. Prominently warn about
   empty/all-skipped replacement and show **Fetched/staged; not applied**.
5. If `changed:false`, show **No policy changes** without auto-submitting.
   Never change sync flags or import report counters as a preview side effect.
6. Explicit Save uses existing `POST /api/v1/transactions` and explicit
   `POST /api/v1/transactions/{id}/confirm`. Omit read-only `software` as usual.
   Discard has no backend write; normal stale-save rebase/review remains required.
7. Explain that applying the staged configuration does not enable recurring
   sync. Recommend disabled automatic policies for initial confidence testing;
   if already enabled, concurrent automatic revisions can cause `409`.

### Coordination and acceptance

- Deploy backend endpoint before enabling the frontend button. No migration or
  compatibility window; no URL/credential input is added to the request.
- Operator must save a valid Sando URL reachable from the daemon. Grant preview
  permissions; additional transaction authority is needed only to apply.
- Check both sync flags false: preview stages mapped replacement while live
  configuration/revision/history, flags/reports and worker status/cache stay
  unchanged. Review, discard, explicit save/confirm and rollback must work.
- Verify manual/other-provider rules and unrelated fields stay unchanged,
  skipped/empty removals are visible, unchanged preview does not save, dirty
  drafts survive, and unauthorized/invalid/upstream/concurrent/stale errors
  never stage success or activate changes.
- Backend automated results are recorded in the
  [journal](../journal/2026-11-24.md). Browser Save / Commit, real Sando and native
  appliance acceptance remain unverified; do not mark this item implemented.
