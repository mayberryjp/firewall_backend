## 2026-11-23-01 Independent automatic Sando policies

- Priority: high. Classification: **required**. Status: **Pending frontend review**.
- Backend availability: unreleased working-tree changes; no commit, release,
  push, deployment or frontend delivery claimed.
- Contract/release impact: additive opt-in configuration/status, stricter
  permissions for delegating firewall automation. Next automatic calendar
  software version; no manual version bump.

### Endpoints and authorization

- `GET /api/v1/revisions/latest` (`config.sando`) and `GET /api/v1/state`
  (`desired.sando`): existing API-key authentication and `state.read`.
  New always-serialized boolean `policy_sync_enabled`, default `false`.
- `POST /api/v1/transactions`, followed by
  `POST /api/v1/transactions/{id}/confirm`: complete current configuration and
  string `base_revision`, not PATCH. Existing `transactions.write` and
  `sando.write`; changing the policy flag (either direction), or changing
  `api_url` while policy sync is enabled before/after, also needs `firewall.write`.
  The same affected-component authorization applies to rollback and
  `POST /api/v1/revisions/{revision}/restore`.
  Submit/confirm retain `202`/`200`; malformed flag `400`, enabled without URL
  `422`, missing authority `403`, stale/busy/drift `409`, existing
  `{error,transaction}` persistence/backend errors.
- `GET /api/v1/sando`: existing `state.read`, no query/body, `200` and `no-store`;
  ordinary `401`/`403`/`400`/`405`/`503` behavior unchanged. New `policies` object;
  existing top-level metadata fields and MQTT sensors retain their meaning.
- No new endpoint or browser call to Sando is needed for automatic sync.
  Daemon outbound `GET <api_url>/api/ignorelist` is a **Sando route**, not a
  Netcontrol API route. No credentials/API keys are forwarded.

### Previous versus current behavior

Previously only `sync_enabled` fetched hourly host metadata/scores. Rules
required a browser-driven reviewed import. The independent policy flag now
polls immediately at enabled startup/enablement/source/relevant-host changes and
every 300 seconds after each completed attempt. Either worker can run alone.

`200` requires a complete JSON array and ETag. Next poll sends `If-None-Match`;
`304` performs no mapping or revision. Successful effective rule changes are
durably applied, verified and immediately confirmed by the daemon, incrementing
the configuration revision once without a browser. Unchanged mapped rules do
not create revisions. Manual import reports do not change.

Only existing-host outbound rules labeled `origin:"import"` and
`import_source:"sando"` are replaced. Preserve manual/other-provider rules,
inventory, defaults, interface rules, input and NAT. Supported rows require
literal same-family unicast source/destination, existing exact source host with
one address in that family, numeric protocol 6/17/1/58, TCP/UDP destination port
1..65535 or ICMP/ICMPv6 recorded zero. Numeric strings are supported; wildcard
addresses/ports, unsupported protocols/ports, unmatched/ambiguous/malformed rows
and duplicates are skipped and counted. IPv6 requires enabled IPv6.

**A valid empty array or zero-supported remainder removes existing Sando-owned
host rules automatically.** This is the explicitly selected skip-and-apply
behavior, not a review queue. Never describe ignore-list entries as an
authoritative universal firewall allowlist or turn wildcard suppression into
broad permits. Response/JSON/ETag/config-limit failures preserve prior settings;
busy or failed applies report errors and retry without advancing the validator.
Normal durable rollback/recovery remains in force.

### Fields and synthetic examples

```json
{"api_url":"https://inventory.example.test/sando","sync_enabled":false,"policy_sync_enabled":true,"hosts_import":null,"rules_import":null}
```

The always-present `policies` member of `GET /api/v1/sando`:

```json
{"enabled":true,"state":"succeeded","sync_interval_seconds":300,"source_url":"https://inventory.example.test/sando","etag":"\"ignorelist-synthetic-token\"","last_attempt_at":"2026-11-23T08:00:00Z","last_success_at":"2026-11-23T08:00:00Z","next_sync_at":"2026-11-23T08:05:00Z","error":null,"imported_count":8,"skipped_count":2,"last_changed_revision":"2026.11.23.4"}
```

- `state`: `disabled|pending|syncing|succeeded|error`, disabled first.
- Nullable RFC3339 UTC attempt/success/next times; next is null while disabled,
  fetching or before scheduling. Success includes unchanged checks.
- `error`: nullable untrusted text. `etag`: nullable opaque string, never parse
  as a version. `source_url`: current configured source; no old-source exposure.
- Counts: ordinary integer JSON numbers, last successfully processed complete
  list, initially zero; unchanged checks preserve them. They are not one-time
  import operation counts.
- `last_changed_revision`: nullable canonical calendar-version string, latest
  effective automatic change in this daemon session, not global latest.
- Policy status/ETag reset on daemon restart; committed rules/revisions persist.
  Startup fetches unconditionally. Errors/disabled sync can retain prior
  counts/success in the current session.

### Frontend work and acceptance

1. Add independent **Automatically sync policies** toggle and rename/help the
   old toggle as **Sync hosts and scores**. Require URL; gate policy/source
   writes on both Sando and firewall authority. Explain unattended application,
   skip behavior, empty replacement and trusted-network prerequisites.
2. Extend client configuration/status types; preserve the new flag in every
   full-package write. Use existing confirmed settings workflow.
3. Show separate metadata and policy panels. Poll the existing status endpoint
   while visible (e.g. 30 seconds; reads do not trigger sync). Show skipped
   counts, errors, nullable times and applied revision without interpreting
   metadata-disabled as policy-disabled. Escape all upstream/error text.
4. Disable one-time **Import rules** while automatic policies are enabled.
   Warn that manual edits to Sando-owned host rules will be reconciled.
   Refresh/rebase stale drafts after automatic revision changes; never blindly
   overwrite a new revision.
5. Test policy-only, metadata-only, both and neither; permission denial,
   missing URL/type errors; `200` apply, `304` no revision, changed-but-equivalent
   list no revision, add/edit/delete/final-empty replacement, skipped/all-skipped
   counts, busy/failure preservation, disable/source changes and daemon restart.
   Verify manual/other-provider/default/input/NAT preservation.

Deploy backend before clients rely on the flag/status. Operators must provide
daemon-to-Sando reachability and Sando's snapshot-consistent conditional GET
contract; HTTP(S), verified TLS, no redirects/proxies, five-second connect and
thirty-second request timeout, 4 MiB/4096-row response limits. Do not expose
unauthenticated Sando publicly. No compatibility window or state migration is
introduced. Keep disabled until the upstream contract and mapping are accepted.
