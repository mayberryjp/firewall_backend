## Browser-free live CLI API-key setup

### Summary and components

Added a root-console key-creation command for configuring LAN addresses/VLANs
over the existing SSH CLI without website onboarding. The user selected live
daemon operation and interactive initial account username/password entry rather
than a shared default password or generated account password.

- [Local control transport/client](../../crates/netcontrold/src/local_control.rs)
  and [daemon lifecycle/options](../../crates/netcontrold/src/main.rs):
  `netcontrold --create-api-key NAME`, default Linux host device socket
  `/run/netcontrol/control.sock`, optional matching `--control-socket PATH`,
  hidden/confirmed password prompts and terminal-only one-time key output.
- [Identity](../../crates/netcontrold/src/identity.rs): reuse key validation and
  construction, atomically save the account/key and complete onboarding.
  [Application](../../crates/netcontrold/src/http.rs) and
  [module registration](../../crates/netcontrold/src/lib.rs): share the live
  locked credential store rather than reopen or edit it externally.
- [Identity tests](../../crates/netcontrold/tests/identity.rs),
  [local transport/PTY/process tests](../../crates/netcontrold/tests/local_control.rs)
  and [CI validation](../../.github/workflows/validate.yml): include the six
  root-required Linux fixtures in the privileged CI gate.
- [CLI guide](../CLI.md#browser-free-local-key-creation),
  [deployment guide](../BUILD_AND_INSTALL.md#optional-configuration-ssh-server),
  [root README](../../README.md#configuration-cli-over-ssh),
  [daemon README](../../crates/netcontrold/README.md#configuration-ssh),
  [frontend contract](../../FRONTEND_SPEC.md#44-transactional-ssh-configuration-cli)
  and [changelog](../../CHANGELOG.md).

### Decisions and current contract

Root authorization is local Unix peer UID plus root-owned private directory
(0700) and socket (0600), with safe parent checks on daemon/client. No TCP
control endpoint, default SSH password, direct state-file editing, daemon restart
or credential-lock bypass is introduced. Foreign/symlink/insecure/active paths
fail explicitly; only a verified stale socket is replaced. Shutdown drains
accepted identity work and removes only the owned socket.

Fresh devices prompt for an account username and password twice, then persist
the completed account plus a full-permission key in one update. Existing account
passwords, keys and sessions are retained. The explicit command completes
pending onboarding, making previously pending keys usable. Normal key limits,
hash-only persistence, fail-closed errors, HTTP/SSH authentication and revocation
remain unchanged; no saved-identity schema change.

The command is Linux root-only, requires terminal output and an updated running
daemon. It does not operate on `--auth-file` scoped credentials, enable disabled
SSH, add firewall permits or configure networking itself. Manual simulator/lab
deployments require an explicit socket path. Lost key output cannot be recovered;
inspect/revoke the named key rather than blindly retry an uncertain outcome.

Recommended release impact: **additive, next automatic calendar version**.
No HTTP methods, schemas, permission names or status codes changed.

## Stable-release installation without CI run IDs

### Summary and components

Fixed the outdated fresh-installer workflow after the user requested ordinary
installation without a CI run ID. This supersedes the earlier chat guidance
that a manual build/artifact upload was necessary: published stable Ubuntu
release assets already exist.

- [Installer](../../install.sh): anonymously resolve the latest stable GitHub
  Release, pin all downloads to its canonical version, verify manifest and
  binary before execution, fetch the service unit from that tag, and check
  compiled version/required options before installation. Replace the `gh`
  dependency with Python 3 metadata validation and remove `--run-id`.
- [Installer regression suite](../../packaging/native/install_tests.sh):
  33 release-download/validation scenarios, five compiled-version/options
  scenarios and no-run-ID/default-CLI checks, alongside existing provisioning,
  service, prerequisite, upgrade/recovery, reset and hardening coverage.
- [README](../../README.md#install-on-ubuntu),
  [installation guide](../BUILD_AND_INSTALL.md#ubuntu-prebuilt-installation-amd64),
  [frontend deployment contract](../../FRONTEND_SPEC.md#41-deployment-contract)
  and [changelog](../../CHANGELOG.md): current download commands and requirements.

### Decisions and current contract

Use the existing two unsigned Ubuntu release assets and trusted HTTPS source
for the tagged service unit rather than add a third release asset, manually
dispatch builds, change publication policy or retain a legacy artifact path.
Reject missing/draft/prerelease/invalid calendar tags, missing/duplicate/foreign
asset URLs, malformed manifests and duplicate/unknown fields, wrong schema/
target/version/types/size/hash/architecture. Downloads are HTTPS-only with
timeouts/size limits; one initial release selection prevents latest-promotion
races between binary, manifest and unit. Only the verified binary is executed.
The SHA-256 is integrity against the same-source manifest, not an independent
publisher signature. Tagged service source uses verified HTTPS from the same
trusted repository. Existing `.ncpkg` signing is unchanged.

No arguments are required; optional paired WAN/LAN and LAN CIDR settings,
native prerequisites, existing-state refusal and transaction recovery remain
unchanged. No network configuration or initial DNS is provided before install.
APT needs internet and supplies Python 3 for installer validation only; native
protocol implementations remain Rust. There is no authentication/run-ID flow
or CI/source fallback. The removed option is rejected.

Recommended release impact: **installer fix with breaking removal of
`--run-id`, next automatic calendar version**. No HTTP, saved configuration or
application authentication/permissions contract changed.

## Safe retry after failed initial network capture

### Summary and components

The user reported a route-protocol rejection during initial capture followed
by the installer refusing the leftover `native-state.json.lock`. Verified in
[core store](../../crates/netcontrol-core/src/store.rs) and
[engine startup](../../crates/netcontrol-core/src/engine.rs) that the stable
lock is created/acquired before initial network capture and journal persistence.
Its presence alone does not establish a saved appliance or an active owner.
No device route/address/customer values are recorded here.

- [Installer](../../install.sh): extract the fresh-install guard; preserve
  existing journal/environment refusal but permit a verified inactive, empty,
  private regular lock when neither journal nor environment exists. Do not
  delete/recreate the lock or bypass the daemon's exclusive lock acquisition.
- [Regression tests](../../packaging/native/install_tests.sh): 14 filesystem
  cases covering no files, unused/active/nonempty/insecure/directory/symlink/
  dangling/hardlinked locks, saved/empty state, environment and symlinked state/
  environment. Use real `flock`, test retry after releasing an active lock, and
  assert retained lock device/inode/size/mode/link count.
- [Install guide](../BUILD_AND_INSTALL.md#ubuntu-prebuilt-installation-amd64),
  [frontend deployment contract](../../FRONTEND_SPEC.md#41-deployment-contract)
  and [changelog](../../CHANGELOG.md): clarify retry versus reinstall boundaries.

### Decisions and current contract

This narrowly corrects the prior blanket rejection of any journal lock.
Root-owned mode-0600 empty singly linked regular files may be reused only when
both saved journal and appliance environment are absent, after a nonblocking
exclusive `flock` check. `flock` is provided by Ubuntu `util-linux`; missing
tooling, permission errors, foreign/symlink/nonempty files and active locks fail
explicitly. The installer does not hold that preflight lock across daemon
startup; the engine independently acquires it and serializes actual state
initialization. No files are removed, state reset, ownership recovery weakened,
or previously rejected network configurations silently adopted.

Recommended release impact: **installer fix, next automatic calendar version**.
No HTTP/API/authentication, saved schema or normal networking behavior changes.
The earlier RA/SLAAC limitation remains: correcting the input configuration is
separate from safely permitting a retry.
