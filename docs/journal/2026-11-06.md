## Browser-free live CLI API-key setup

### Summary and components

Added a root-console key-creation command for configuring LAN addresses/VLANs
over the existing SSH CLI without website onboarding. The user selected live
daemon operation and interactive initial account username/password entry rather
than a shared default password or generated account password.

  [frontend contract](../../FRONTEND_SPEC.md#44-transactional-ssh-configuration-cli)

### Decisions and current contract

Root authorization is local Unix peer UID plus root-owned private directory
(0700) and socket (0600), with safe parent checks on daemon/client. No TCP
control endpoint, default SSH password, direct state-file editing, daemon restart
or credential-lock bypass is introduced. Foreign/symlink/insecure/active paths
fail explicitly; only a verified stale socket is replaced. Shutdown drains
accepted identity work and removes only the owned socket.

Fresh devices prompt for an account username and password twice, then persist
the completed account plus a full-permission key in one update. Existing account
passwords, keys and sessions are retained. The explicit command completes
pending onboarding, making previously pending keys usable. Normal key limits,
hash-only persistence, fail-closed errors, HTTP/SSH authentication and revocation
remain unchanged; no saved-identity schema change.

The command is Linux root-only, requires terminal output and an updated running
daemon. It does not operate on `--auth-file` scoped credentials, enable disabled
SSH, add firewall permits or configure networking itself. Manual simulator/lab
deployments require an explicit socket path. Lost key output cannot be recovered;
inspect/revoke the named key rather than blindly retry an uncertain outcome.

Recommended release impact: **additive, next automatic calendar version**.
No HTTP methods, schemas, permission names or status codes changed.

## Safe retry after failed initial network capture

### Summary and components

[core store](../../crates/netcontrol-core/src/store.rs) and
[engine startup](../../crates/netcontrol-core/src/engine.rs) that the stable
lock is created/acquired before initial network capture and journal persistence.
Its presence alone does not establish a saved appliance or an active owner.
No device route/address/customer values are recorded here.

- [Installer](../../install.sh): extract the fresh-install guard; preserve
  existing journal/environment refusal but permit a verified inactive, empty,
  private regular lock when neither journal nor environment exists. Do not

- [Regression tests](../../packaging/native/install_tests.sh): 14 filesystem
  cases covering no files, unused/active/nonempty/insecure/directory/symlink/

- [Install guide](../BUILD_AND_INSTALL.md#ubuntu-prebuilt-installation-amd64),
  [frontend deployment contract](../../FRONTEND_SPEC.md#41-deployment-contract)
  and [changelog](../../CHANGELOG.md): clarify retry versus reinstall boundaries.

### Decisions and current contract

This narrowly corrects the prior blanket rejection of any journal lock.
Root-owned mode-0600 empty singly linked regular files may be reused only when
both saved journal and appliance environment are absent, after a nonblocking
exclusive `flock` check. `flock` is provided by Ubuntu `util-linux`; missing
tooling, permission errors, foreign/symlink/nonempty files and active locks fail
explicitly. The installer does not hold that preflight lock across daemon
startup; the engine independently acquires it and serializes actual state
initialization. No files are removed, state reset, ownership recovery weakened,
or previously rejected network configurations silently adopted.

Recommended release impact: **installer fix, next automatic calendar version**.
No HTTP/API/authentication, saved schema or normal networking behavior changes.
