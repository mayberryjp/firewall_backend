## Browser-free live CLI API-key setup

### Summary and components

Added a root-console key-creation command for configuring LAN addresses/VLANs
over the existing SSH CLI without website onboarding. The user selected live
daemon operation and interactive initial account username/password entry rather
than a shared default password or generated account password.

- [Local control transport/client](../../crates/netcontrold/src/local_control.rs)
  and [daemon lifecycle/options](../../crates/netcontrold/src/main.rs):
  `netcontrold --create-api-key NAME`, default Linux host device socket
  `/run/netcontrol/control.sock`, optional matching `--control-socket PATH`,
  hidden/confirmed password prompts and terminal-only one-time key output.
- [Identity](../../crates/netcontrold/src/identity.rs): reuse key validation and
  construction, atomically save the account/key and complete onboarding.
  [Application](../../crates/netcontrold/src/http.rs) and
  [module registration](../../crates/netcontrold/src/lib.rs): share the live
  locked credential store rather than reopen or edit it externally.
- [Identity tests](../../crates/netcontrold/tests/identity.rs),
  [local transport/PTY/process tests](../../crates/netcontrold/tests/local_control.rs)
  and [CI validation](../../.github/workflows/validate.yml): include the six

### Decisions and current contract

Root authorization is local Unix peer UID plus root-owned private directory
(0700) and socket (0600), with safe parent checks on daemon/client. No TCP
control endpoint, default SSH password, direct state-file editing, daemon restart
or credential-lock bypass is introduced. Foreign/symlink/insecure/active paths
fail explicitly; only a verified stale socket is replaced. Shutdown drains
accepted identity work and removes only the owned socket.

Fresh devices prompt for an account username and password twice, then persist
the completed account plus a full-permission key in one update. Existing account
passwords, keys and sessions are retained. The explicit command completes
pending onboarding, making previously pending keys usable. Normal key limits,
hash-only persistence, fail-closed errors, HTTP/SSH authentication and revocation
remain unchanged; no saved-identity schema change.

The command is Linux root-only, requires terminal output and an updated running
daemon. It does not operate on `--auth-file` scoped credentials, enable disabled
SSH, add firewall permits or configure networking itself. Manual simulator/lab
deployments require an explicit socket path. Lost key output cannot be recovered;
inspect/revoke the named key rather than blindly retry an uncertain outcome.

Recommended release impact: **additive, next automatic calendar version**.
No HTTP methods, schemas, permission names or status codes changed.

### Validation

Used stable Rust and the committed lockfile in disposable network-disabled
Linux Docker containers with existing repository Cargo/toolchain caches. No
dependency changes or installs were needed. Windows has no local Rust toolchain;
the root socket feature is deliberately Linux-only.

- Initial fixtures correctly rejected a private directory directly under
  world-writable `/tmp`; moved test directories under `/run` without weakening
  production checks.
- PTY tests exposed a hidden-input prompt/echo-toggle race; set terminal mode
  before displaying the prompt and restore it on ordinary input/write errors.
  A malformed-request test exposed internally tagged unit-variant acceptance
  of extra fields; use a strict empty-object status variant. Corrected test-only
  inherited PTY descriptors/test placement and the reported Clippy issue.
- `cargo +stable test -p netcontrold --locked --offline --quiet`:
  **176 passed, 11 ignored**. Includes existing SSH, CLI, HTTP, identity and
  worker behavior.
- `cargo +stable test -p netcontrold --test local_control --locked --offline --quiet -- --ignored --test-threads=1`:
  **6 passed**: exact interactive command, hidden/confirmed passwords,
  immediate HTTP/shared-resolver use, persistence/revocation, concurrent key
  writes, strict framing, scoped-mode refusal, UID/path protections, stale
  sockets, bounded idle shutdown and actual daemon SIGTERM cleanup.
- After final acceptance assertions,
  `cargo +stable test -p netcontrold --locked --offline --quiet --test identity --test local_control -- --include-ignored --test-threads=1`:
  **9 identity + 6 root local-control tests passed**. Includes password mismatch
  without partial setup, retained existing sessions, and exact unauthenticated
  `/auth/status` login/configured response after local setup.
- `cargo +stable clippy -p netcontrold --all-targets --locked --offline -- -D warnings`,
  `cargo +stable build -p netcontrold --locked --offline` and
  `cargo +stable fmt --all -- --check`: **passed**.
- `git diff --check`: **passed**.

Full workspace, Linux-native networking fixtures, musl release packaging,
Windows compilation and hosted CI were not rerun for this daemon-only feature.
The process fixture uses the simulator: it verifies control/HTTP/shutdown, not
physical NIC networking or an installed appliance. No browser UI acceptance
or on-device deployment performed.
