  debug builds, incremental compilation and a persistent checkout-local target
  cache/lock. No Git fetching, prerequisite installation or service-unit changes.
  Default deployment requires an active standard service; build-only mode does

  staging failure, restart failure and active-check failure cases; failed
  staging never stops the service, and restart/check failures restore the old
  bytes and attempt restart. No real services touched. Rust compilation and
  real Ubuntu/systemd/connectivity recovery not executed on this Windows host;
  no Docker used. Full Rust checks not rerun: no Rust code changed.
- Frontend impact: none; API/schema/authentication and service paths unchanged.
  This is an opt-in operator development workflow, not a frontend requirement.

- Summary: firewall diagnostics confirmed an installed binary but no systemd
  unit and no running daemon. Requiring manual unit/directory commands made
  the intended single-command development workflow incomplete.
- Components: [upgrader](../../in-place-upgrade.sh),
  [existing shell tests](../../packaging/native/install_tests.sh),
  [README](../../README.md),
  [build guide](../BUILD_AND_INSTALL.md#incremental-ubuntu-development-upgrades),
  [changelog](../../CHANGELOG.md).
- Decisions/current contract: build and smoke-check first. For `LoadState=not-found`,
  install the repository's unit, private directories and sbin directory, reload
  systemd and discover the effective executable. Do not overwrite an existing
  unit, unmask a service or replace an unmanaged daemon. Support a missing binary
  and inactive/failed service. Back up an existing binary and stage/replace/start
  the build. Failed deployment restores the previous binary if present (otherwise
  removes the new binary), restarting only a previously active service. Retain
  newly created unit/directories for retry; never delete state/credentials.
  Catchable-failure recovery remains best effort, not persisted-state rollback.
  No boot enablement, Git fetch, prerequisite provisioning or Docker introduced.
  Supersedes earlier requirements that an active service already exist; the
  prebuilt installer's separate no-start behavior is unchanged.

  Mocked cases cover missing/loaded/masked services, conflicting units, unmanaged
  processes, unit-install/reload failures, first deployment, inactive existing
  binary, failed first/inactive starts and prior active-upgrade recovery cases.
  No real privileged paths or services touched. Real Ubuntu builds, systemd,
  network connectivity and power-loss recovery unverified on this Windows host;
  Rust checks not rerun because no Rust code changed.
