## Ubuntu systemd service installation

- Summary: filled the Ubuntu service gap by adding a unit and integrating it
  into the source installer. Supersedes the earlier binary-only bootstrap
  description above; standalone existing-checkout binary installation remains
  binary-only.
- Affected files: [unit](../../packaging/native/netcontrold.service),
  [installer](../../install.sh), [installation guide](../BUILD_AND_INSTALL.md),
  [README](../../README.md), and [changelog](../../CHANGELOG.md).
- Decisions/current contract: require running systemd; install a root native
  host-mode unit with HTTP on `0.0.0.0:8080`, journald, restart on failure,
  `0077` umask and a 60-second stop timeout. Create private state/services/key
  directories and reload systemd without starting/enabling/restarting. Preserve
  runtime data, existing drop-ins and boot-enabled state; reject differing unit
  files and symlinks. State/credential paths match manual Ubuntu startup.
  Document management exposure and service-only setup without rebuilding.
  Recommended version bump: minor; no release baseline assigned.
- Validation: Git Bash syntax/help/invalid-argument/non-Linux checks passed.
  Mocked service installation passed: private directories, unit mode/path and
  daemon-reload, no start/enable calls and no host filesystem changes. A conflict
  propagation check initially failed because conditional Bash calls suppress
  errexit; explicit return fixed it and the same check passed with no side
  effects. Unit command/path invariants, documentation links and
  `git diff --check` passed; editor reports no new errors. Real Ubuntu
  `systemd-analyze verify`, systemd start/stop,
  restart, boot, permissions and native recovery remain untested on Windows.
  No Rust changes; Rust tests not run.
- Frontend impact: none; no API, schema or UI changes. Existing management
  exposure and native prerequisites remain; new service commands are operator
  documentation only. No new frontend handoff required.
- Open issues/next steps: commit/push only with user authorization; until then
  new GitHub URLs/content are not available. Verify on Ubuntu with a console,
  onboard, check connectivity/recovery, then explicitly enable at boot. No
  commit, push, release or frontend notification performed.
