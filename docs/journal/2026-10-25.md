# Journal - 2026-10-25

## Azure Dynamic DNS

- Summary: implemented Azure public DNS Dynamic DNS after consulting pfSense
  client guidance/Azure setup and Microsoft OAuth/record-set REST documentation.
  User selected **IPv4 A records only**, supporting both direct interface
  monitoring and NAT-aware public-IP detection. No external helper process.

  [core model/validation/tests](../../crates/netcontrol-core/src/dynamic_dns.rs),

- Contract: new `config.dynamic_dns` array (default empty, max 32), required Azure
  tenant/client UUIDs, private secret reference, public zone resource ID, relative
  hostname/`@`, source interface/mode, TTL 30..86400 seconds and interval
  60..86400 seconds; optional standard metadata. New `dynamic_dns.write`;
  `POST /api/v1/services/dynamic-dns/secrets` creates an immutable reference,
  `GET /api/v1/services/dynamic-dns/status` uses `state.read`. Ordinary confirmed
  transactions/revisions/restores carry settings, never plaintext credentials.
  Existing transaction unknown-field pruning remains unchanged, including
  accidental inline secrets; credential upload/persistence remain strict.
- Decisions: service-principal OAuth client credentials, public Azure endpoints,
  fixed HTTPS ipify NAT detection; source IPv4 and Linux device binding fail
  closed, with host-resolver DNS explicitly not interface-bound. Up interface
  must have exactly one usable IPv4; non-public published results refused.
  TLS verification required, redirects/proxies disabled, five-second connection
  and 15-second request timeouts, bounded bodies. Sequential checks retry after
  configured interval; each reads Azure, skips unchanged IP/TTL, preserves
  metadata, uses conditional ETag/create writes and refuses alias/multi-address
  record sets. No force-update endpoint, AAAA, wildcard or private DNS support.
- Lifecycle/persistence: confirmed settings only, pause/cancel observations during
  configuration/maintenance, joined shutdown; simulator has no network I/O,
  namespace-mode entries rejected. Disable/delete never removes Azure records;
  external writes already sent/completed cannot be undone by configuration
  rollback. Owner-only plaintext secrets in `<state>.dynamic-dns`, max 256,
  immutable and retained for revisions; back up with journal, no read/delete/
  automatic pruning API. Missing credentials fail explicitly.
