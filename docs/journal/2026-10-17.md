## Default-enabled allow-all IPv4 ICMP

### Summary and decisions

- Added `config.firewall.allow_all_icmp`, defaulting to true for omitted/null
  input and normalized to an explicit boolean.
- User confirmed input, output, and forwarding scope, not forwarding alone.
  Match IPv4 protocol 1 with no interface/address/type/code restrictions;
  ICMPv6 protocol 58 is not included.
- The implicit forward exception precedes legacy and host/interface rules.

  traffic. Disabling removes the exception, not a blanket ICMP block.

  transaction semantics. Validate existing owned firewall state and reject

## Per-interface DHCPv4 relay

### Summary and decisions

- User selected IPv4 configuration **and a working managed service**, not
  metadata-only settings; chose an operator-installed daemon.
- Added `dhcp_relay: { enabled, servers }` per interface. Default disabled;
  valid disabled server lists persist. All servers receive requests.
- Validate canonical distinct IPv4 unicast targets even when disabled. Enabled
  relay requires an up dummy/VLAN interface with IPv4 and at least one server.
  No WireGuard client-facing relay, DHCPv6, or custom server ports.
- Select `giaddr` from the first lexicographically sorted canonical IPv4 prefix;
  reject duplicate selected addresses among enabled interfaces.
- Linux supervises one non-root, capability-limited, relay-only dnsmasq process
  in the managed namespace, with DNS/system config disabled. Source semantics
  verified against the [dnsmasq manual](https://dnsmasq.org/docs/dnsmasq-man.html).

  Rollback, startup, and explicit repair use stored committed/pending settings.

  DHCP server reachability or lease delivery.
- Explicit operator binary/runtime/UID/GID requirements, runtime locking,
  parent-death handling, bounded output, safe PID inspection, and targeted
  child-only termination. No adoption/killing of arbitrary PIDs.
- Added status/repair endpoints and simulator states. Since runtime repair
  covers all services, check every enabled service's permission under the engine
  lock rather than authorize against a potentially stale snapshot.

## Native dual-stack gateway monitoring

### Summary and decisions

- User approved native ICMP monitoring after discussing dpinger's aggregate
  standard deviation versus consecutive-probe RTT variation. Selected IPv4 and
  IPv6, JSON API first, configurable recommended health policy, and no automatic
  route failover. No dpinger process/package dependency is introduced.
- Added independent persistent `gateway_monitors` with enabled toggle, explicit
  interface/source/gateway/target/table, bounded timing/window settings, and
  configurable loss/latency/optional-variation thresholds plus failure/recovery
  holds. Disabled settings remain validated and retained.
- Enabled monitors require declared routes/source-policy rules and an up
  managed interface with the configured source. Native sockets bind to source/
  interface in the managed namespace and verify effective FIB table/interface/
  next hop before each send. A local path/socket failure is unavailable/Unknown,
  not remote gateway Down. External network mutations remain unsupported drift.
- Added opt-in `-gateway-monitoring` and raw-socket capability preflight.
  Native monitoring needs existing namespace privileges plus `CAP_NET_RAW`;
  no additional Alpine package or workflow dependency is needed.
- Metrics: rolling sent/received/lost/pending, fractional loss, RTT min/max/mean,
  population standard deviation, nearest-rank p50/p95, and mean absolute RTT
  difference over adjacent successful transmitted probes. Loss/pending gaps
  never bridge variation pairs. Missing metrics are null, genuine zero remains
  numeric zero, and late/duplicate/foreign replies do not improve measurements.
- Default full-window warmup is 30 seconds. Health is Unknown during warmup,
  Down at 100% finalized loss, Degraded at 20% loss or 150 ms average RTT;
  optional variation threshold defaults disabled. Failure/recovery holds default
  3/5 seconds. Rolling-window effects add to hold time.
- Worker/sample/health states are separate. Cached statistics reads perform no
  probes or full observation; gateway collection releases the engine lock.
  Stale/failed/simulated samples never imply current real reachability.
- Network changes stop workers before writes; affected settings/repair/restart
  reset in-memory history. Unchanged monitor workers survive unrelated service
  edits. Health never mutates desired configuration, routing, or modeled drift.
- Added `gateway_monitors.write`, configuration/runtime/status/statistics APIs,
  and explicit service repair. All shared repair endpoints authorize every
  enabled service under the engine lock.
- Corrected a related native lifecycle bug: relay reconciliation was inside the
  softflowd loop. It now executes independently, followed by monitor startup.
- Recommended feature bump: minor; relay reconciliation correction is patch.
  Aggregate Unreleased remains major; no release number assigned.

## Appliance NTP, remote syslog, and dual-scope vnStat

### Decisions and implementation

- User selected appliance clock synchronization only (no serving), whole-system
  remote logs including backend logs, and vnstatd covering all host and managed
  namespace interfaces. Explicitly selected host networking for NTP/syslog and
  netcontrold-owned chronyd/syslog-ng rather than host OpenRC service management.
- Added default-disabled persistent `ntp`, `syslog`, `vnstat` settings, validated
  retained lists, numeric/lowercase-DNS hosts, maximum 8 unique servers, explicit
  UDP/TCP/TLS ports/transports, and `ntp.write`/`syslog.write`/`vnstat.write`.
- Native supervision requires root, `-allow-host-services`, trusted operator
  binary paths, private runtime/persistent directories, and a fixed exclusive
  host lock. Refuses competing clock clients and unowned `/dev/log`; never
  stops/adopts arbitrary processes or edits their configuration.
- NTP is slew-only client mode with no network command listener or NTS.
  Clock changes are host-global and cannot be undone by configuration rollback.
- Syslog-ng reads system/kernel/internal sources and the arranged backend log
  file, preserves local messages, and forwards to every destination. TLS trust
  is required; IPv6 literals explicitly choose IPv6, DNS uses IPv4 default.
  Running does not prove clock synchronization, complete capture, or delivery.
  Disabling the managed logger also stops its local logging.
- vnstatd has separate host/managed databases, initial full interface seeding
  using the vnstat CLI, and 5-second inventory reconciliation including loopback/
  pseudo-interfaces excluded from upstream auto-discovery. Errors log and mark
  unhealthy, not successful coverage. Poll/update is 5 seconds, save/rescan
  1 minute. Managed database names include boot/namespace identity.
- Restart/disable/repair preserves databases and stops/joins owned children and
  inventory workers. Removed histories are not automatically deleted; abrupt
  termination can lose unsaved data or require ownership/socket cleanup.
- Added configuration/status/shared-repair APIs and `runtime.appliance_services`.
  Simulator persists settings without real time/logging/history activity.
  All repair endpoints authorize every enabled service under the engine lock.
- Recommended bump: minor for new functionality; aggregate Unreleased remains
  major. No release baseline/version assigned.
