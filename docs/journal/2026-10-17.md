# Change journal: 2026-10-17

## Default-enabled allow-all IPv4 ICMP

### Summary and decisions

- Added `config.firewall.allow_all_icmp`, defaulting to true for omitted/null
  input and normalized to an explicit boolean.
- User confirmed input, output, and forwarding scope, not forwarding alone.
  Match IPv4 protocol 1 with no interface/address/type/code restrictions;
  ICMPv6 protocol 58 is not included.
- The implicit forward exception precedes legacy and host/interface rules.
  Input/output exception chains have accept defaults, preserving other local
  traffic. Disabling removes the exception, not a blanket ICMP block.
- User explicitly chose automatic enabling for older saved configurations,
  including configurations that previously blocked ICMP.
- Added retryable startup migration, preserving explicit values and pending
  transaction semantics. Validate existing owned firewall state and reject
  unrelated drift before atomically rebuilding it. Persist migration completion;
  preserve the existing single initial journal write on successful startup.
- Recommended release bump: **major**, because the enabled default broadens
  accepted traffic for existing deployments. Baseline unknown; remains Unreleased.

## Per-interface DHCPv4 relay

### Summary and decisions

- User selected IPv4 configuration **and a working managed service**, not
  metadata-only settings; chose an operator-installed daemon.
- Added `dhcp_relay: { enabled, servers }` per interface. Default disabled;
  valid disabled server lists persist. All servers receive requests.
- Validate canonical distinct IPv4 unicast targets even when disabled. Enabled
  relay requires an up dummy/VLAN interface with IPv4 and at least one server.
  No WireGuard client-facing relay, DHCPv6, or custom server ports.
- Select `giaddr` from the first lexicographically sorted canonical IPv4 prefix;
  reject duplicate selected addresses among enabled interfaces.
- Linux supervises one non-root, capability-limited, relay-only dnsmasq process
  in the managed namespace, with DNS/system config disabled. Source semantics
  verified against the [dnsmasq manual](https://dnsmasq.org/docs/dnsmasq-man.html).
- Changed bindings stop before networking edits; services start afterward.
  Rollback, startup, and explicit repair use stored committed/pending settings.
  PID/namespace/owned UDP 67 checks provide local readiness; they do not prove
  DHCP server reachability or lease delivery.
- Explicit operator binary/runtime/UID/GID requirements, runtime locking,
  parent-death handling, bounded output, safe PID inspection, and targeted
  child-only termination. No adoption/killing of arbitrary PIDs.
- Added status/repair endpoints and simulator states. Since runtime repair
  covers all services, check every enabled service's permission under the engine
  lock rather than authorize against a potentially stale snapshot.
- Feature-level bump recommendation: minor; earlier Unreleased changes still
  recommend major. No version assigned and no compatibility path introduced.

## Alpine APK build, installation, and automatic CI

### Summary and decisions

- User requested a build/install specification and automated GitHub builds;
  selected lightweight Alpine Linux and native Alpine packages.
- Target Alpine 3.23 `x86_64` and `aarch64`, with a static stripped daemon,
  embedded onboarding website, OpenRC service, and root-managed configuration.
- Install in loopback-only simulator mode, without auto-start or boot enablement.
  Native mode requires an operator-provisioned isolated namespace and a separate
  scoped journal. No automatic namespace creation, host-network management,
  state deletion, or reboot recovery was added.
- GitHub Actions runs on pushes, pull requests, and manual dispatch. Linux/
  Windows checks and isolated privileged integration gate native Alpine builds
  and package-install/OpenRC smoke tests. No releases or deployments.
- Use development APK identifiers `0_git<commit timestamp>-r0`, not an invented
  SemVer baseline. Upload commit/toolchain provenance, SHA-256 checksums, and
  ephemeral signing public keys; private keys remain temporary and are removed.
  A stable signing/repository publication policy is not configured.
- No redistribution license was inferred: APK metadata explicitly states
  `LicenseRef-Unspecified`.
- Found and fixed a deployment-blocking bug: DHCP relay initialization was
  nested under softflowd initialization. They now initialize independently;
  the existing relay-only Linux lifecycle test explicitly asserts this.
