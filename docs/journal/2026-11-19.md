## Dense Experience summary read timeouts

- Summary/why: valid `limit=256` hourly summaries exceeded the common 900 ms
  SQLite budget. Its progress handler produced raw `interrupted`, while
  explicit checks produced `experience query read deadline exceeded`; both
  surfaced as HTTP 503 through the external device proxy. Reproduced the
  failure with 256 hosts and 360 retained ten-second buckets.
- Components: [store, decoding, budgets and regressions](../../crates/netcontrol-native/src/experience_store.rs),
  [canonical frontend contract](../../FRONTEND_SPEC.md),
  [detailed Experience contract](../PROTECTED_HOST_EXPERIENCE_SPEC.md#821-one-hour-per-ip-summaries),
  [validation guide](../../README.md#build-and-validate),
  [changelog](../../CHANGELOG.md) and
  [handoff 2026-11-19-05](../frontend-handoffs/2026-11-19.md#2026-11-19-05-large-experience-summary-read-budget).
- Decisions: two bucket/address-ordered cursors stream samples and coverage
  reasons in one transaction. Reuse bounded per-host string allocations and
  identical previously validated score JSON only within that request. Preserve
  nanosecond UTC timestamps, canonical counters, validation, source evidence,
  retained pooled histograms, requested order and missing-slot semantics.
  No all-history buffer, partial-success fallback or omitted hosts.
- Optimizations alone did not fit a dense 256-host hour into 900 ms. The user
  explicitly approved 900 ms per started 64-host batch, capped at 3600 ms for
  256 selected hosts. This supersedes the earlier page-wide 900 ms summary
  requirement; empty/at-most-64-host pages and other Experience reads retain
  900 ms. Default 25/max 256, one-hour retention, pinned cursors, four shared
  read slots, 4 MiB output, storage-lock/busy bounds and persistence remain.
  Normalize summary SQLite interruptions to the descriptive deadline error.
- Contract/release impact: read-timing contract fix, next automatic calendar
  version; no schema, configuration, authorization, HTTP path or public-version
  seed change. The aggregation cap is not an end-to-end HTTP deadline.
- Frontend impact: required client/device-proxy timeout review, with changes
  conditional on existing timeouts; handoff 2026-11-19-05 is Pending frontend
  review. Allow more than 3.6 seconds plus lock, snapshot/metadata, serialization
  and network overhead; retain pagination and nonoverlapping polls. The external
  proxy implementation is outside this repository.
