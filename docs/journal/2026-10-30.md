## Firewall rule origins, with imports owned by the frontend

### Summary and scope

Added persisted rule-source labels so the frontend can distinguish manual policy
from Sando/other imports without the backend acquiring, replacing or reordering
rules. The user explicitly limited backend scope to labels and appropriate tags

  rows with saved labels and generated setting/default/bypass rows as system.

- [Frontend contract](../../FRONTEND_SPEC.md#firewall-rule-origins),
  [README](../../README.md), [changelog](../../CHANGELOG.md) and
  [frontend handoff](../frontend-handoffs/2026-10-30.md#2026-10-30-01-rule-origins-and-frontend-sando-replacement).

### Decisions and current contract

- Origins are manual/import/system/inherited; omitted input means manual.
  Nullable import_source is required for import, matching
  `[a-z][a-z0-9_-]{0,63}`; other origins require null/omission.
  Sando's provider ID is sando, not its URL. Wrong types/unknown or null origin
  return 400; typed source/origin validation failures return 422.
- Labels are descriptive, not authorization or verified source identity. Normal
  full-package writes can still edit/delete any rule with existing component
  permissions. No new endpoint, merge protection, importer or background
  firewall synchronization was added.
- Backend-generated counter rows use system/null; configured rows retain saved
  labels. Interface rules keep their original ownership when projected as
  inherited on a host; the frontend renders that effect without persisting
  derived duplicate rules. Historical deny records are unchanged.
- Frontend replacement removes only Sando-owned rules, preserves manual rules/
  other providers, keeps manual-first/source-order lists without changing scope
  precedence, reviews successful empty/partial imports, leaves prior state intact
  on acquisition failure, and uses ordinary confirmed transactions/revision
  conflict handling. Previous Sando target lists with no new rules are included
  in replacement. No unrelated host inventory/input/NAT deletion.
- **Release impact:** recommended minor (additive schema/response fields);
  Unreleased, baseline unknown. No version bump, release, commit, tag, push,
  deployment or frontend notification performed.

- Decisions/current contract:
  - Keep the existing optional nonnullable endpoint string. Accept canonical
    numeric sockets, empty/omitted roaming endpoints and lowercase ASCII DNS
    names with an explicit canonical port 1..65535. Reuse hostname validation;
    no URLs, trailing dot, underscores, zones or mapped IPv6. Wrong types/null
    remain 400 and invalid syntax is 422.
  - Resolve enabled peers in the managed namespace using the existing bounded
    Rust hosts-file/UDP A/AAAA/CNAME resolver; no shell/external WireGuard or
    DNS daemon/dependency. Expose the resolver to the native crate without
    changing its existing service callers. IPv6 disablement permits only IPv4
    results/resolvers. Disabled peers are not resolved/refreshed.
  - Refresh immediately and after 60-second waits between cycles. Keep a
    still-advertised selection; otherwise select deterministically with IPv4
    preference. Persist successful selections in private native state for
    restart/rollback. Initial uncached lookup/persistence failure fails normal
    backend apply (500 transaction/rollback outcome); later failures retain the
    last-good selection and expose timestamped per-peer errors.
  - Update only endpoints of matching device/peer identities. Preserve keys,
    keepalives and static/BGP-owned AllowedIPs, including prefixes installed
    after the DNS supervisor was configured. Stop/join before reconfiguration,
    recovery, rollback or deletion; cancellation prevents late refresh writes.
  - DNS selections/authenticated roaming are dynamic runtime state, not numeric
    endpoint drift. Keep strict drift checks for configured numeric endpoints.
    Preserve names in desired/observed configuration, revisions and exports.
    New native `runtime.wireguard_dns` reports running/interval/worker error and
    per-peer configured/selected endpoints, family policy and last attempt/
    success/error. Actual roaming endpoints remain in runtime WireGuard rows.
    No new HTTP method/path, permission, config flag, interval form or MQTT schema.
  - DNS must work on the underlay before first use; no search-suffix, TCP/DoH
    fallback or TTL-driven interval is added. Do not remove private state to
    bypass schema/recovery errors. No release seed/version metadata was changed.
