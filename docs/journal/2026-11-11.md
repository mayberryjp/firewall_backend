### Decisions and current contract

New `GET /api/v1/logs/syslog` and `GET /api/v1/logs/netcontrol` require separate
`logs.read`, not `state.read`/`syslog.write`/`firewall.logs.read`. Default latest
100 entries; strict limit 1..500 and 1024-byte query, optional stable cursor.
Entry strings contain sequence, UTC capture time and message text. Forward
pages are strictly after the cursor; gap/reset markers and oldest-history
checkpoint avoid invented continuity. 512 KiB serialized-entry page budget,
complete response under 1 MiB, 65,000-byte UTF-8 messages. Explicit 400/401/403/
405/503 and standard error/no-store behavior. Simulator logs are unsupported.
No configuration/persisted network schema/revision/default changes.

Each stream retains four 2 MiB segments plus identity/lock metadata, with one
temporary extra segment during rotation. Appends use `sync_data`; Linux
directory changes are synchronized. Empty interrupted rotation does not expire
valid old records. Incomplete/corrupt files and external/link/public-path
ownership changes fail explicitly, without unknown-file deletion/reset.
Failed storage writes make that sink unavailable until restart; incomplete
retained data additionally needs operator repair. Old `backend.log` and
`syslog-host.log` remain untouched, without import/compatibility readers.

Local capture runs with host-services opt-in and valid inherited systemd socket
even when `syslog.enabled:false`; that flag governs remote connections/sends
only. Runtime/status/MQTT `forwarding_enabled` separates that flag from capture
worker state. Active capture can be explicitly restarted with `system.restart`,
retaining history. Previously captured records are not replayed on enable.
Worker/configuration restarts still reset operational counters.

**Correction/superseding decision:** the earlier syslog-counter task's local
append/no-per-record-fsync description is superseded here: captured records now
advance after local append and `sync_data`. Names/units/reset semantics remain.
History identity/sequences do not reset with worker counters.

Direct Netcontrol history includes daemon/native/worker diagnostics. The socket
stream may contain their journald stderr copy, so streams are separate but not
disjoint. Standalone helper/local-key/conversion CLI output and pre-logging
startup failures are not captured by the direct daemon sink. No journal cursor/
replay, arbitrary filesystem reads, redaction guarantee, complete capture,
tamper-evident auditing or remote-delivery acknowledgment added. Log-reading
keys must be restricted; third-party text can be sensitive.

Release impact/recommended bump: **additive read APIs and breaking logging-path/
capture-worker-state deployment contract; next automatic calendar version**,
Unreleased. No version seed/Cargo identity edits, commit/push/tag/publication,
frontend notification or running-appliance change.

**Frontend impact: required**, log views/client types/permission help, separate
polling cursors, retention/reset notices, safe rendering and syslog capture/
forwarding labels. [Item 2026-11-11-05](../frontend-handoffs/2026-11-11.md#2026-11-11-05-persistent-socket-and-netcontrol-log-apis)
is **Pending frontend review**, not sent or acknowledged.
