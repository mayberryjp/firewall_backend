# Journal: 2026-10-23

## Physical Interface Inheritance and Native DHCPv4

### Summary and Decisions

Implemented an unreleased Linux draft for automatic physical-NIC inheritance at
first native host startup. The user requested preserving current configuration,
retaining DHCP as DHCP, exclusive Netcontrol IP/DHCP ownership and initial
`unassigned` roles. New journals and unused empty revision-zero journals can
capture a baseline; configured journals are not recaptured or reset.

Capture requires networkd/resolved, no competing NetworkManager, supported
physical/unmastered NICs and active finite DHCPv4 leases. Static IPs/routes,
client identity, hostname, route metric and supported resolver options are
inherited; unsupported dynamic IPv6, policy rules or manager settings fail
explicitly. Wi-Fi association remains with its supplicant. This is not general
hotplug discovery or an OS-network-manager compatibility layer.

Per-NIC networkd exclusions and a durable adoption receipt protect ownership
handover/retry. NIC identity and DHCP preferred-source checks precede handover.
Completed adoption without its core journal fails rather than reconstructing
stale state. Caught failures attempt snapshot/route/manager recovery; outstanding
recovery errors retain durable evidence. Existing native transaction/firewall
ownership checks remain. Stop/removal does not automatically return DHCP to the
OS manager; console-assisted hand-back is an operator action.

DHCPv4 runs in-process using mozim, with the existing netlink stack, durable
leases/update intents, bounded worker lifecycle and renewal/rebind/expiry/NAK
handling. A local Apache-2.0 vendor patch propagates upstream-swallowed NAKs.
Current lease addresses/routes are runtime state, not static configuration.
Top-level `dhcp_clients` and `dns` maps use `interfaces.write`; shared service
repair now additionally checks that permission when either map is configured.
Resolver publication uses systemd-resolved D-Bus, not a DNS server/subprocess.
The captured lease includes its exact kernel connected-subnet route, so changing
the address to NOPREFIXROUTE does not silently remove gateway reachability.
Unrelated kernel routes are not adopted.

Recommended version bump: **major**, for the initial ownership/deployment,
persisted schema and frontend contract changes. Baseline unknown; no version
assigned, release approved, commit/push/tag or notification performed.

## Correct Default Policy-Rule Rejection During Inheritance

The supplied journal identifies the replacement's fatal startup error as
`automatic inheritance cannot preserve custom policy routing`, before ownership
handover. Earlier IPv6 netlink attribute-size warnings also appeared during
successful HTTP operation; they are not the reported fatal error. This narrows
the earlier deployment diagnosis; it does not establish the restored service's
current health or prove the host has no genuinely custom rules.

Found a deterministic false rejection in
[check_initial_policy_rules](../../crates/netcontrol-native/src/linux/networking.rs):
the attribute allowlist rejected `SuppressPrefixLen(u32::MAX)`. Linux initializes
default-rule suppression to -1 and emits that disabled sentinel as uint32 in
rule dumps. Verified the semantics against
[kernel fib_rules.c](https://raw.githubusercontent.com/torvalds/linux/master/net/core/fib_rules.c)
and the locked netlink crate's attribute decoder. Accept only disabled
`SuppressPrefixLen`/`SuppressIfGroup` values on otherwise standard
priority/table pairs. Active suppression, nonzero selectors, flags, non-table
actions, unknown attributes and custom priority/table pairs remain rejected.
No rule is deleted, rewritten or silently ignored. Errors now include the
offending rule for any remaining unsupported configuration; review runtime
details before sharing diagnostics.
