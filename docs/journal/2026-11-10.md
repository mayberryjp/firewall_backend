### Decisions and current contract

Always overwrite conflicting live delays in host mode and persist
`/etc/sysctl.d/99-netcontrol-panic.conf` as root-owned mode 0644. Reclaim both
live and owned-file drift every second without rewriting unchanged files.
Do not delete/edit foreign sysctl files, change panic-on-oops/warning/NMI/lockup
triggers, or deliberately induce a panic. Boot ordering can temporarily override
the file until daemon startup; competing writers can win between checks.

Startup takeover errors abort startup. Later failures log/retry and appear in
runtime/platform health; they do not gate unrelated valid transactions.
Policy is not editable configuration or part of transaction rollback. Stop
joins the worker but leaves the live/boot settings in place, without restoring
foreign originals. Simulator and lab namespaces, including host-tunable opt-in,
do not take over this host-global control.

`GET /api/v1/runtime` retains `state.read` and adds nullable native
`kernel_panic` with live seconds/drift, fixed desired delay/interval, worker
state/retry/error and persistence path. Simulator omits it. No new methods,
write fields, permissions, saved configuration schema or status codes.
Native-host startup during installation, all upgrade paths, restart and boot
establishes policy; no shell-script-only implementation or external worker.

Release impact/recommended bump: **breaking deployment policy with additive
runtime metadata; next automatic calendar version**, Unreleased. No seed or
Cargo package version changes.

### Decisions and current contract

Supersedes earlier AppArmor-enabled-by-default documentation **only for fresh
installation**. Existing standalone hardening's explicit opt-out is unchanged;
source/binary/HTTP/signed-package upgrades and reset do not establish this policy.
Prior kernel-panic work in this day's journal remains unchanged.

Require supported GRUB, verify `apparmor=0` on generated Linux boot commands,
and verify the running kernel reports disabled/no AppArmor module and no active
AppArmor LSM where exposed. If enabled, prepare boot disablement then stop with
manual reboot/rerun instructions, before AppArmor purge or Netcontrol provisioning.
Do not silently claim a stopped service disables existing kernel enforcement.
GRUB failure restores the previous owned drop-in; generated output still needs
operator inspection. No automatic reboot or custom kernel.

Once disabled, mask the service even if absent, purge explicit AppArmor
policy/tooling families (including residual configuration), remove the documented
standard profile/cache/state paths, and pin tooling to APT priority -1 with
candidate checks. Keep required `libapparmor1` and built-in kernel code.
Reapply/verify the persistent service mask after purge, since package maintainer
scripts can remove masks; the purge fixture explicitly simulates that removal.
Reject essential/protected/incomplete packages, unrelated dependency removals,
package installations in purge plans, unsafe paths and unverifiable results;
explicitly disable autoremove. Preserve unrelated packages and APT configuration.

This removes confinement protection for the whole host. A root operator,
direct package install or replacement boot configuration can override persisted
policy; do not promise literal permanent absence. Completed mutations and
deleted custom profiles are not automatically backed up/rolled back.
No HTTP/auth/schema/status-code or saved firewall configuration changes.
