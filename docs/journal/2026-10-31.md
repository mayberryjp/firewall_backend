### Decisions and current contract impact

- GET `/api/v1/interface-capabilities` requires `state.read` and returns the
  saved snapshot or null; never automatically scans.
- POST `/api/v1/interface-capabilities/refresh` requires `state.read` and
  `interfaces.write`, no body/query, and returns 200 only after durable save.
  Wrong input/method/auth uses 400/405/401/403. Fatal scan/persistence failures
  use 503/500 and retain prior data. Upgrade/restart POST guards remain.
- Finalized a separate collection path to avoid shadowing resource GET for a
  valid interface named `capabilities`; no alias for the preliminary path.
- Store only the latest snapshot separately from desired config in the existing
  checksummed, owner-only journal. No revision advance, networking apply or
  rollback of inventory. Partial completed scans replace old evidence with
  explicit source errors; timestamps/boot IDs identify cached observations.
- Include all links, driver/firmware/bus and PCI numeric identity, NUMA,
  supported/advertised/partner link-mode bits with Mbps/duplex, channels/queues,
  software steering, XDP flags and named offload state. Retain future unknown
  mode bits. No guessed marketing names, PMD claims or external dependencies.
- DPDK/accelerated RFS/generic XDP/AF_XDP copy readiness remain unknown pending
  dedicated validation. Advertised support is not proof of operational readiness
  or benefit. No tuning, rebinding, BPF attachment or active packet tests.
- Sysfs evidence is host-mode only; lab namespace omissions are explicit.
  Limit inventory to 8192 interfaces/queues, feature strings to 4096 entries,
  bounded kernel buffers, two-second netlink receive waits and elapsed scan
  checks. Blocking driver ioctls are not forcibly cancelled.
- **Release impact:** additive, Unreleased; next automatic calendar version,
  no manual bump. No commit, push, tag, release or notification performed.
