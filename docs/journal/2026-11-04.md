## Software metadata isolation from native startup ownership

### Summary and components

The reported fatal startup error is the native ownership comparison, distinct
from the preceding `IFLA_INET6_CONF` size warnings. Found that the operational
projection retained daemon-managed `software` metadata, while release checks
save new metadata without applying native configuration. This can leave core
and native configurations differing solely in release metadata. Appliance state
was not retrieved, so its exact persisted difference remains unverified.

- [Core projection](../../crates/netcontrol-core/src/model.rs) excludes
  `software`, using the existing ownership-read projection rather than editing
  persisted ownership or introducing a fallback.
- [Model regressions](../../crates/netcontrol-core/src/model_tests.rs) cover
  running-version changes, successful/failed checks, saved metadata preservation,
  projection roundtrips and continued detection of actual MTU differences.
- [Native host regression](../../crates/netcontrol-native/src/linux/host_integration.rs)
  checks metadata-only apply/observe without ownership-file writes or intents,
  and reboot reconciliation against recorded differing software metadata while
  retaining the real-network mismatch rejection and rollback/recovery coverage.
- [Native operator guide](../../crates/netcontrol-native/README.md#ownership-and-reconciliation)
  and [Unreleased changelog](../../CHANGELOG.md) explain the fix.

## DHCP-following route gateways

### Summary and components

Added explicit `"gateway":"dhcp"` for configured IPv4 routes so a site change
does not leave an endpoint host route pinned to the previous DHCP router.
Literal gateway routes are unchanged and are not automatically converted.

- [Core route/IPv6 validation](../../crates/netcontrol-core/src/model.rs),
  [model tests](../../crates/netcontrol-core/src/model_tests.rs) and
  [transaction tests](../../crates/netcontrol-core/src/engine_tests.rs):
  accept the exact token only with IPv4 and DHCPv4 on the same managed Ethernet
  interface, even when disabled; preserve saved/history values, permissions,
  confirmation and rollback.
- [Native route validation](../../crates/netcontrol-native/src/model.rs),
  [lease plans/worker](../../crates/netcontrol-native/src/linux/dhcp_client.rs),

  [boot reconciliation](../../crates/netcontrol-native/src/linux.rs):
  resolve effective gateways under the shared lease lock; remove only known
  previous/next protocol-242 routes, install after DHCP routes and verify readback.

### Decisions and current contract impact

**Additive, Unreleased**, next automatic calendar version; no manual seed or
version bump. `gateway` remains a string, with exact lowercase `"dhcp"` as an
explicit mode rather than a new optional field or compatibility path. Omitted
or empty remains direct; numeric gateways remain pinned.

Select the lowest-metric table-254 IPv4 default route from the same interface's
valid matching lease; equal-best routes must agree on one numeric unicast gateway.
No default, a direct default, invalid gateway or differing equal-best gateways
is an explicit error. Classless lease routes remain authoritative; never use
the DHCP server, another WAN or a retained static gateway as fallback.
No valid lease suspends installation, retaining enabled configuration.
Lease changes never rewrite saved gateway/destination/table/metric/revision.
Prevalidate candidate route resolution before publishing a lease intent.

No automatic table/metric changes, policy rules, AllowedIPs edits or WireGuard
endpoint-loop prevention are added. Operators must review underlay routing and
explicitly transact any conversion from a pinned gateway. Existing address/
ownership drift guards still apply; this does not repair or adopt temporary
manual appliance changes. No credentials or appliance state were accessed.

### Decisions and current contract impact

**Additive, Unreleased**, next automatic calendar version; no manual seed/version
bump. New desired fields are optional/unmanaged unless explicitly configured.
Reuse complete candidates, current revision, confirmation/deadline, history,
rollback and existing `transactions.write`, `interfaces.write`,
`kernel.host.write`. No standalone enable endpoint or external ethtool process.
Automatic host ownership is availability only, not automatic tuning or API
authorization; labs cannot use host sysfs to tune physical NICs.

RFS is for local socket consumers: explicit global/per-queue zero/power-of-two
counts up to 1048576, at most 64 queues and configured sum within global budget;
positive queues require nonzero RPS on the same queue. Global changes affect
other local applications. NIC controls use at most 32 managed physical Ethernet
interfaces and exact allowed Linux feature booleans. Unsupported/fixed settings,
unsafe LRO enabling, incoherent dependencies, unexpected side effects, stale
identity and unreadable controls fail explicitly. All active/requested original
bits, including latent wishes, are preserved; no automatic dependent-feature
edits or blanket offload profile. Failed recovery retains its durable intent.

Diagnostic fields expose configured RFS/offloads, global table evidence and queue
table sizes. Native runtime identity/requested-bit metadata is not editable
configuration. Cached capabilities remain a distinct timestamped snapshot.
No ALTQ, CAKE/FQ-CoDel, HTB, IFB, RSS/XPS, IRQ or datapath-bypass work is included.
