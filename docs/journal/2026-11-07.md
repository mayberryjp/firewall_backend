## Friendlier installer and upgrade output

### Summary and affected components

The user requested more color, shorter messages and output focused on material
installation work instead of routine informational chatter.

- [Installer](../../install.sh): shared cyan stage, green completion, yellow
  warning and red failure labels; quiet successful commands; failed-step output
  and exit status; shorter prompts, help and setup summary.
- [Source upgrade](../../upgrade.sh): reuse installer output helpers for build,
  staging, backup, service setup and restart. Keep recovery diagnostics and
  previous-binary/log locations.
- [Shell regressions](../../packaging/native/install_tests.sh): output/color,
  exit-status, interruption and temporary-log cleanup coverage; file-based
  deployment traces account for isolated step execution; assert quiet upgrade
  success and visible staging/restart failures.
- [Build/install guide](../BUILD_AND_INSTALL.md#installer-and-upgrade-output)
  and [Unreleased changelog](../../CHANGELOG.md): document the output behavior.

### Decisions and current contract

Enable ANSI colors only for terminal stderr with non-dumb `TERM` and no nonempty
`NO_COLOR`. Redirected output stays plain; status labels use stderr, final setup
URLs and binary/log locations use stdout. Capture each step's routine stdout/
stderr in a private temporary file, replay it on failure and remove it afterward.
Long builds show one stage rather than per-crate progress.

Retain actionable console/connectivity, automatic security-update disablement,
Snap/syslog, SSH exposure and LAN-client warnings. Installation policy, daemon
configuration, permissions, upgrade backup/recovery and service health checks
are unchanged. Explicitly stop installation if a wrapped stage fails.

Release impact/recommended bump: **presentation-only CLI improvement; next
automatic calendar version**, Unreleased. **Frontend impact: none**; no API,
schema, browser workflow or deployment prerequisite changes. No handoff needed.
