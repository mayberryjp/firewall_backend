### Decisions and contract impact

Reuse existing `kernel.host`/`kernel.namespace` maps, catalog, HTTP confirmed
transactions, SSH commands, permissions and native ownership/recovery. No new
write endpoint, broad sysctl access, auto-tuning or configuration defaults.

`nf_conntrack_max` is host-global, not namespace-isolated; configure it only
under host ownership (1024..16777216 entries). TCP established/close/close-wait/
fin-wait/last-ack/time-wait and UDP unreplied/stream timeouts are namespace-scoped
(1..604800 seconds). Values remain canonical strings. Numeric bounds are not
hardware memory-sizing advice; low timeouts require explicit operator review.
Read-only count, hash buckets and TCP validation-relaxation settings remain
unsupported. Native preflight also rejects out-of-range captured originals
rather than silently clamping them.

No connection flush, hash-table resize, sysctl.d writes or external helper
processes. Existing durable native intents handle pre-write capture, exact
readback, rollback, restart repair and ownership removal. Restoring settings
cannot resurrect expired connections. Existing API status/authentication and
confirmation semantics are unchanged.

### Decisions and current contract

The rotating native table persists but evicts records. Use an independent
private schema-1 SQLite index with full exact tuple bytes, including address
family and null-port distinction; never expire keys on time, rotation, restart
or disable. Seed currently retained history without alerts; pre-feature already
evicted history cannot be reconstructed. Capture while disabled still indexes
tuples; enabling is not history backfill. Source port/interfaces/chain/reason
are deliberately excluded. Index and outstanding alerts grow with distinct
traffic; disk/schema/corruption errors remain explicit, with no silent reset.

Webhook URLs are secret bearer credentials. Reuse the private credential-store
pattern, exposing only device-local `webhook_ref` in configuration. Strict
HTTPS discord.com webhook validation; no arbitrary origin, redirects, URL read,
test-send or secret export. Upload `201`, status `200`, new `discord.write` for
upload/configuration, existing transaction and status permissions/lifecycle.
No native network-policy change, automatic port opening or third-party program.

Only committed native-host configuration sends; simulator never posts and
active configuration/upgrade work pauses sending. Up to ten bounded embeds per
message, mentions disabled, packet metadata only. HTTP 429 explicitly retries
three times after advertised bounded delay; ambiguous transport/non-429 failures
do not retry. Claim queued records before network I/O to avoid duplicate replay;
delivery is best-effort and interrupted/uncertain attempts can be lost. Unclaimed
queued first records survive restart; disabling clears pending delivery but
preserves seen keys. Accepted Discord messages cannot be rolled back. Managed
restart and health/status surface worker failures; shutdown cancels waits/I/O.

Release impact/recommended bump: **additive contract/private-state deployment
requirement; next automatic calendar version**, Unreleased. Build-derived
software identity unchanged. **Frontend impact: required** toggle/private URL
upload/ref types, permission controls, status/errors, permanent dedup/privacy

### Decisions and current contract

All nine supported tuning keys are owned on native host installation/startup,
including upgrades. Capture missing values, not catalog minima or guessed
performance defaults; preserve/reapply saved values. Initial capture is saved
before takeover and retained as native originals. Saved-host additions commit
through existing apply/verify/recovery as `system-conntrack-ownership`,
`applying_local` then `committed`, with null deadline and a new configuration
revision. Complete ownership is a no-op on subsequent startup.

Validate that each local ownership transaction adds exactly missing conntrack
keys without changing saved values or unrelated configuration, including when
loading a durable intent. Existing private credentials are preserved without
requiring managers to have loaded their stores before startup reconciliation.
Capture/read/validation/preflight/apply errors remain explicit; failed claims
roll back under normal recovery. Pending user transactions are not confirmed,
overwritten or interrupted by a claim.

Normal HTTP/SSH edits keep their scoped permissions and confirmation timer.
Removing a key restores its original, but the next native host startup reclaims
it from current values; no permanent opt-out. Simulator and explicit lab
namespaces do not auto-own. Accounting/checksum prerequisites remain separate.
No connection flush, hash resizing, relaxed TCP validation, external sysctl
worker, unrelated sysctl-file deletion or configuration reset.

Release impact/recommended bump: **breaking host ownership/startup policy;
next automatic calendar version**, Unreleased. No manual version bump.
**Frontend impact: required** captured-value/default messaging, nullable local
transaction display and refreshed revisions after upgrade.

is **Pending frontend review**, not sent or acknowledged.
