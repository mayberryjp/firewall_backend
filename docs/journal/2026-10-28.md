- Contract/decisions:
  - `POST /api/v1/processes/restart`, strict `{target}`, permission
    `system.restart`. Selected native supervisors stop/join before replacement;
    unrelated workers stay untouched. Async MQTT/Dynamic DNS/system controllers
    acknowledge `202`, drain before restarting, and remain explicitly
    restartable after attempt errors/panics; failures remain in platform health.
    Generation counts requests, not completed restarts; draining requests can
    coalesce. Disabled targets are not enabled by restart.
  - Whole-daemon restart is only attached in native host mode with an active
    systemd watchdog. It gates mutations, gracefully drains HTTP/SSH/workers,
    durably shuts down and exits nonzero for the existing packaged
    `Restart=on-failure` policy. No `systemctl`, subprocess or arbitrary PID/name
    control. Other launch modes return explicit unavailability.
  - `POST /api/v1/diagnostics/dns-lookup`, permission `diagnostics.run`, requires
    interface/hostname, A or AAAA (default A), timeout 100..5000 ms (default
    2000). Uses configured-first/valid matching DHCP DNS, override/global IPv6
    policy, at most 16 servers, no public fallback. Direct UDP/53 with TCP
    truncation fallback, bounded attempts and two concurrent jobs. Engine lock
    is released before network I/O; response includes captured revision/scope.
  - RTT measures DNS request/response including resolver processing, not ICMP.
    TCP fallback RTT excludes connect/previous UDP; elapsed includes all work.
    First valid DNS response stops attempts, including negative/error rcodes.
    Transport/protocol failures try remaining servers and remain explicit in
    attempts; all-failed diagnostic is `200 status:"failed"` with null RTT.
    Simulator never fabricates timings.
  - Both actions preserve desired configuration/revisions and reject active
    transactions/recovery/upgrades/restarts. Restart resets selected ephemeral
    state, not persistent accounting databases; lease reacquisition/delivery
    gaps remain possible. No new installer changes needed: DNS uses existing
    sockets and daemon restart uses the existing supervised service policy.

- Contract/decisions:
  - `firewall.nat.destination_rewrite` is an ordered array (default empty,
    maximum 256). Requires original `out_interface` WAN, TCP/UDP protocol, one
    `destination_port`, LAN `target_interface` and `target_address`; target
    determines family. Validates managed/up roles, family, static target subnet,
    usable host address, non-firewall target and unique WAN/protocol/port/family.
    Existing `nat.write` covers operational and metadata edits.
  - Prerouting FIB destination/source/mark lookup identifies original WAN
    before DNAT; actual destination routing and normal filters remain. No local
    output NAT, port change, implicit accept, source NAT or conntrack flush.
    Targets must route replies through the firewall; same-subnet direct replies
    are not automatically repaired. Existing translations survive edits and
    rollback until expiry/deletion.
  - rustables 0.9 does not expose a constructible FIB expression. Encode only
    destination-rewrite rules using Linux UAPI and append them within the same
    typed nftables atomic batch. Reuse bounded native netfilter transport with
    exact ACK-header checks, kernel sender checks, deadline and error handling;
    reserve a bounded 4 MiB receive queue for batch ACK overhead (host limits
    can cap the actual allocation). No dependency/lockfile changes.
  - Native fingerprint ownership, provisional persistence, recovery and rollback
    paths are reused. CLI stages the same complete candidate. Target interface
    is subnet/reference validation, not a routing override. Forwarding, FIB/NAT
    kernel support and real return paths remain operator prerequisites.

- Decisions/current contract:
  - Transactional `config.bgp` with `bgp.write`, local/remote ASN (four-octet
    capability), router ID, static local IPv4/interface selection, keepalive/
    hold seconds (30/90 defaults), per-neighbor default import flag, at most
    32 neighbors and 1..16384 accepted paths globally (default 4096).
    Peering uses native interface-bound active/passive TCP179 and bounded
    parsing/queues, hold expiry and reconnect. BGP uses keepalives, not hellos.
  - Export connected IPv4 networks from configured/live up interfaces,
    including current DHCP addresses; refresh approximately two seconds.
    No static/learned-route redistribution. Basic eBGP/iBGP receives direct-
    next-hop paths, rejects loops/defaults without opt-in and bounds capacity.
    Deterministic local best-path selection; MED exposed, not selected on.
  - Selected routes use Linux main table 254, owned protocol 245, metric 200.
    WireGuard neighbors explicitly reference an enabled peer public key.
    Bootstrap neighbor AllowedIPs/routes remain static prerequisites; union
    learned prefixes only into that peer, reject cross-peer overlap, preserve
    configured AllowedIPs. Dynamic prefixes also authorize incoming source
    addresses, so peers must be trusted.
  - Withdraw/session loss/hold expiry, restart, disable, apply/rollback and
    shutdown remove owned runtime additions, not desired config/revisions.
    A private journal records old/new ownership before mutation; recovery
    occurs only after native scope validation. Periodic incremental audits
    restore missing owned routes/AllowedIPs and surface foreign conflicts.
    Netlink route snapshots are batched instead of dumped once per prefix.
  - `GET /api/v1/services/bgp` (committed config), `/services/bgp/status`
    (applied summary) and `/routes/bgp` (accepted/alternate learned path rows,
    selected/installed/reason/source), all under `/api/v1`, require `state.read`,
    reject query parameters and non-GET methods. Static route API unchanged.
    Existing restart API accepts `bgp` with `system.restart`. CLI candidate/
    show commands, simulator, runtime/appliance-service row, shared health/
    alerts and aggregate statistics/MQTT summary are wired. Full route tables
    are not MQTT publications. Peer unavailability is a warning, not a global
    transaction-health lock.
  - Existing root native service/socket/netlink/WireGuard prerequisites suffice;
    no installer scripts/modules or helper service required. Operators provide
    trusted TCP179 permits, underlay connectivity and bootstrap routing.
