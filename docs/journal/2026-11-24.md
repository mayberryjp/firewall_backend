## Watching CI and fixing the Sando scheduling regression

- Summary/why: user requested watching CI and fixing/repushing failures.
  [Run 45414367448](https://github.com/mayberryjp/firewall_backend/actions/runs/45414367448)
  for `1a6b4ff0282ebe7a0d2772d6795e08fbf966b501` failed the daemon-library
  `policy_worker_runs_independently_every_five_minutes_and_stops` test while
  waiting for its second request; other build/package/privileged jobs passed.
- Root cause: successful policy status becomes visible inside blocking
  transaction completion, before its async worker rejoins and calculates the
  next deadline. Yielding ten times does not synchronize with that completion.
  Advancing the virtual clock at that point can push the next deadline another
  five virtual minutes into the future.
- Components: [Sando worker regression](../../crates/netcontrold/src/sando.rs)
  and [changelog](../../CHANGELOG.md).
- Decision: test-only notification after next-poll scheduling; await it before
  pausing/advancing time and after the second request. Keep the existing
  five-second guards and all cadence, validator, revision, disablement and
  shutdown assertions. No production code, scheduling or timeout change.
- Contract/release impact: test-only fix, recommended bump **none**; ordinary
  automatic calendar version generation remains unchanged.
- Frontend impact: **none**; no API/schema/status/permissions/workflow change.
  Existing frontend actions remain pending; no new handoff.
- Local validation: `git diff --check` passed. No host Rust toolchain is
  installed; required Rust formatting/tests/Clippy/build and privileged
  validation will run in CI after the user-authorized repair push. No new
  Docker/WSL test resources were created. Follow-up CI is in progress; no
  success claimed until verified.
