    Software identity has one embedded source, independent of Cargo's required
    internal SemVer. Configuration initialization uses iteration 1; same-day
    confirmations increment, later UTC days start at 1. Transactions persist
    nullable `committed_revision`; revision fields/cursors are JSON strings.
    Conflict detection, history chain validation, recovery, authorization and
    provisional rollback remain. Restore confirms a new revision. Clock
    regression/iteration exhaustion explicitly prevent confirmation.

    remain untouched and are refused, not reset or automatically converted.
    The existing policy-rule-removal tool now validates the current schema
    and preserves revision IDs; it is not a numeric-version migration.
  - `desired.software` saves running/latest versions, repository, nullable
    availability, last-check timestamp and errors. The daemon manages it;
    clients omit it or echo its current value, differing nondefault values
    return `422`. Daily metadata changes do not allocate revisions/apply
    networking, invalidate CLI drafts or roll back with historical settings.
  - With existing trusted self-upgrade configuration, async GitHub latest-stable
    discovery runs at startup and every 24 hours. Requests are HTTPS-only,
    no redirects, 10-second connect/30-second total timeout, 1 MiB maximum JSON.
    Failures are logged and saved with unknown availability, never a false
    successful no-update result. Shutdown cancels in-flight discovery.
    Discovery does not verify assets or install software. Upgrade requests
    must exceed both running and last-successful versions.
