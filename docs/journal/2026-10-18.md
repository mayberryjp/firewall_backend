## Rust-only backend and native packaging rewrite

### Summary and decisions

- User requested a complete native Rust rewrite, custom packaging, no protocol
  daemon supervision, no backward compatibility and no retained Go implementation.
  Replaced the implementation with a five-crate Rust workspace and removed Go
  sources/tests/module manifests and old Alpine APK packaging.
- This supersedes Go/APK/external-daemon implementation details and proposed
  future APK checks above; those entries remain historical. User-facing API-key
  naming, wildcard networking CORS, same-origin account management and HTTP on
  `0.0.0.0:8080` remain deliberate current behavior.
- Native services implement DHCPv4 relay, bounded slew-only NTP, syslog forwarding,
  persistent traffic counters/history, NetFlow 1/5/9/IPFIX and ICMP monitoring.
  Kernel networking uses direct namespace/netlink/nftables/WireGuard APIs.
  OpenRC starts the single Rust daemon; no protocol program is executed.
- Custom Ed25519-signed `.ncpkg` tooling implements strict build/verify/install,
  ownership receipts, durable installation rollback and interrupted recovery.
  Installation does not reset application state or automatically start services.
- Explicit persisted schemas reject incompatible/corrupt data without import,
  reset or deletion. Required fields/unknown fields/null validation, worker
  states/no PIDs, service metrics, traffic endpoints and double-hyphen CLI
  contracts are recorded in the canonical frontend specification and handoff.
- Recommended bump: major; baseline unknown, no release assigned. Cargo `0.0.0`
  is unassigned development metadata. No compatibility window is provided.
- Licensing blocker: native `rustables` is GPL-3.0-or-later; no project
  distribution license was assigned. Combined-work licensing/source/notice review
  is required before binary distribution. CI artifact upload is manual opt-in,
  disabled for ordinary push/PR runs.
