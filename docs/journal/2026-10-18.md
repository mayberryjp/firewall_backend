## Cross-origin networking API

### Summary and decisions

- User requested avoiding CORS failures or allowing all origins after device
  onboarding. The networking API previously had no CORS support.
- Added `Access-Control-Allow-Origin: *` to `/api/v1/` responses in both auth
  modes, including errors. GET/POST preflights with Authorization/Content-Type
  return empty 204 before authentication; unsupported methods/headers explicitly
  return 405/400. Exposed Location, WWW-Authenticate, and Retry-After.
- Actual bearer authentication, permissions, setup completion, and revocation
  remain enforced. Cookie credentials are not enabled cross-origin; `/auth/`
  and the embedded website keep existing same-origin protection.
- Recommended bump: minor for new cross-origin client support; aggregate
  Unreleased recommendation remains major. No version baseline assigned.
