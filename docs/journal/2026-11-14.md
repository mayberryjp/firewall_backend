### Decisions and current contract

Use the committed webhook even when automatic alerts or capture are disabled.
No raw URL, candidate reference, request fields, new permission, configuration
switch or persistence schema. Native host mode and an available worker
(`ready`, `paused`, `disabled`) are required; simulator never posts.

`200` after Discord HTTP `200`/`204` returns
`{delivered:boolean,backend_version:string,config_version:string,failed:string}`.
Success clears only Discord's delivery error and resets `failed` to `"0"`.
Version values identify the request's compiled backend and committed snapshot.
Normal two-second health sampling then removes the delivery warning; other
component warnings and later failures remain visible. Alert counters still count
alert entries, not test messages; failed tests preserve those counts and report
delivery errors. Ordinary successful alerts continue clearing only the error.

`401`/`403` auth/permission, `405` wrong method, `400` query/body,
`409` active transaction/upgrade or no saved webhook, `503` unavailable
mode/manager/storage/worker, changed Discord configuration or delivery failure.
Reuse fixed Discord origin, no redirects, connect/request timeouts and existing
rate-limit-only retries. Do not automatically retry the endpoint: an interrupted
request or configuration change can occur after Discord accepts a message.

### Decisions and current contract impact

Do not fabricate or rewrite archived event timestamps in the permanent fix.
Checksum, state/provenance, canonical revision chain and confirmation interval
checks remain strict. Regressed revision dates still produce the existing
clock error before native application. Confirmation expires on either UTC or
monotonic time; restart reconstruction grants no more than the original
10..300-second interval and cannot recover elapsed monotonic time across reboot.

WireGuard DNS status selection/attempt/success values may now be null before
the first successful resolution. Failures remain visible and retries preserve
the last successful endpoint; `running` means worker liveness, not connectivity.
Cache persistence/corruption failures remain explicit errors. DNS underlay must
eventually work independently of the tunnel.

Foreign VLAN collisions still require explicit operator repair; do not
automatically adopt, delete or rename an externally owned management link.
This protection is not a guarantee of interruption-free configuration apply.

Host logging policy uses persistent storage, 128M system use, 256M keep-free,
32M runtime use and seven-day retention targets. Full installer/source upgrade
establishes these files; binary-only HTTPS updates do not. Flush failure aborts
installation explicitly. No daemon dependency on invoking `journalctl` was
introduced, and previously lost volatile logs cannot be recovered.

deployment requirements, plus startup/rollback safety fixes; next automatic

### Decisions and current contract

- Additive `GET /api/v1/statistics/host-experience/latest` and
  `GET /api/v1/statistics/host-experience/history`, requiring `state.read`.
  The latest route has bounded, identity-pinned pagination; history requires a
  canonical IP and returns exactly 360 observed/missing ten-second slots.
  The schema is `netcontrol-host-experience/v1`. See the
  [exact queries, response fields and errors](../PROTECTED_HOST_EXPERIENCE_SPEC.md#8-http-apis).
- Only explicitly protected addresses behind committed, managed LAN interfaces
  are eligible. IPv4 and IPv6 are independent series. Responses include observed
  attachment/VLAN, device metadata and original local-description classification.
  Removed history retains its configured name and protection status.
- Exact counters are decimal strings, unavailable observations are null with
  explicit coverage/status, and low-traffic idle hosts do not receive invented
  good scores. Passive retransmission, ACK RTT, window and DNS evidence produces
  explainable scores across up to six complete buckets; drops are advisory.
  Histogram percentiles are estimates, not exact stored event percentiles.
- Separate packet observation, SQLite writing and bounded streaming conntrack
  work prevent polling, disk access or conntrack dumps from blocking the observer.
  Actual connection completion time/duration and generation/freshness checks
  prevent stale connection counts from appearing current.
- Committed-configuration transitions pause collection before networking changes.
  Shutdown joins workers and checkpoints storage; final engine state is still
  saved if optional telemetry shutdown fails. Paused maintenance continues expiry.
- Real Linux validation exposed and corrected nft LOG attribute widths/IDs,
  combined-batch sequence numbers, large IPv6 element batching and RTNETLINK
  creation outside the Tokio context. Regressions also cover DNAT DNS destination
  IP/port restoration, idle last-seen preservation, failed-worker detection,
  fair bounded evidence allocation and sustained successful DNS request turnover.
- Reads release the engine lock before SQL/metadata enrichment. Four concurrent
  experience reads are allowed; contention returns 429. Storage lock acquisition
  and SQL busy/statement execution are individually bounded; startup integrity
  checking is asynchronous, not subject to a one-second startup promise.
  Either route explicitly fails with 503 above the 4 MiB serialized body ceiling.

  32 MiB WAL budget. Expired pages remain allocated for reuse; no hot vacuum or

  **76,877,402 bytes**, below 80 MiB on the tested x86-64 target. This is not
