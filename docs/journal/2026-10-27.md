- Decisions/contract: retry preparation/runtime errors, unexpected exits and
  unwind panics with cancellable 1..30-second exponential backoff. Attempts
  lasting 60 seconds reset delay. Errors remain visible with optional `retrying`,
  `restart_count`, `last_error`; sample availability is not invented. Native
  verification checks exact applied config and owned active supervisors, not
  network delivery or health. Shutdown/disable prevents retries; resources reopen
  inside pinned namespaces. mDNS retires stale sockets then recovers automatically.
  Syslog destinations reconnect independently; local capture/other collectors
  continue, missed deliveries count without replay. Structural activation/opt-in,
  validation, ownership, TLS, packet admission, authorization, network drift,
  persistence and transaction recovery guards remain. No reset/migration or
  deliberate daemon termination for service unavailability added.

  baseline unknown, Unreleased only. No version bump, commit, push or release.

- Contract/decisions: HTTP state/runtime gain ephemeral `process_health` and
  `active_alerts`, not desired-config fields; new authenticated `state.read`
  cached `GET /api/v1/platform/status` avoids engine lock/observation. Deduplicated
  sanitized active alerts preserve first-seen, clear on observed recovery, retain
  native failures through failed collection. Approximately two-second sampling;
  15-second monotonic stale detection means unknown, not healthy. Covers native
  workers/DHCP errors and daemon manager status/task completion, without resource
  thresholds or an editing policy. MQTT carries shared objects, HA health/count
  sensors, and partial samples when statistics fail; no fabricated counters,
  entity removal, backlog or claims of remote delivery. Failed/unknown health
  does not alter configuration, confirmation/rollback or transport availability.
- Watchdog: systemd notify READY after HTTP bind; WATCHDOG after completed engine
  ticks, STOPPING on listener shutdown. Unit and install/full-source-upgrade
  drop-in configure 60-second watchdog, kill/restart only on stalled process
  progress or crash, five-second retries/no start-rate limit, 180-second startup,
  no core dumps. Manual/no-notify mode is optional/no-op. Worker warnings do not
  trigger restarts; long engine-blocking work must be qualified against timeout.
  Existing persistence/security/rollback guards are unchanged. No data migration,
  additional process, OS service restart, commit, push or release performed.
- Release: minor recommended for additive runtime/API/MQTT/deployment behavior;
