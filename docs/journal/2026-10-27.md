# Journal - 2026-10-27

## Resilient Service Supervision

- Summary: user requires an available firewall with independently recovering
  services and factual status, not global health policy. Previous one-shot worker
  exits and running-only verification let connectivity/runtime failures block
  unrelated configuration workflows. This supersedes historical fatal-runtime/
  repair-only decisions in the 2026-10-25 journal and associated handoffs.
- Components: [supervisor/tests](../../crates/netcontrol-services/src/worker.rs),
  [manager/tests](../../crates/netcontrol-services/src/lib.rs),
  [syslog/tests](../../crates/netcontrol-services/src/syslog.rs),
  [NTP tests](../../crates/netcontrol-services/src/ntp.rs),
  [service native fixtures](../../crates/netcontrol-services/src/integration.rs),
  [mDNS fixtures](../../crates/netcontrol-services/src/mdns/linux.rs),
  [native verification](../../crates/netcontrol-native/src/linux.rs),
  [native regression](../../crates/netcontrol-native/src/linux/integration.rs),
  [service README](../../crates/netcontrol-services/README.md),
  [mDNS spec](../MDNS_SPEC.md), [frontend spec](../../FRONTEND_SPEC.md) and
  [changelog](../../CHANGELOG.md).
- Decisions/contract: retry preparation/runtime errors, unexpected exits and
  unwind panics with cancellable 1..30-second exponential backoff. Attempts
  lasting 60 seconds reset delay. Errors remain visible with optional `retrying`,
  `restart_count`, `last_error`; sample availability is not invented. Native
  verification checks exact applied config and owned active supervisors, not
  network delivery or health. Shutdown/disable prevents retries; resources reopen
  inside pinned namespaces. mDNS retires stale sockets then recovers automatically.
  Syslog destinations reconnect independently; local capture/other collectors
  continue, missed deliveries count without replay. Structural activation/opt-in,
  validation, ownership, TLS, packet admission, authorization, network drift,
  persistence and transaction recovery guards remain. No reset/migration or
  deliberate daemon termination for service unavailability added.
- Release: minor recommended for additive status fields/availability semantics;
  baseline unknown, Unreleased only. No version bump, commit, push or release.
- Validation so far (Linux Docker, locked/offline): `cargo test -p
  netcontrol-services --locked --offline worker::tests`: 3 passed; `cargo test -p
  netcontrol-services --locked --offline`: 63 passed, 15 ignored. Seven native
  mDNS fixtures passed with `NETCONTROL_INTEGRATION=1`, `--network none`,
  NET_ADMIN/SYS_ADMIN, fresh namespaces. Native network-only apply/observe/
  rollback regression passed with SYS_TIME explicitly dropped: NTP reported
  error/retrying while all configuration operations completed. Workspace test
  suite passed. First attempt was blocked by stopped Docker; started local
  Docker Desktop. First compile exposed one-shot test captures; fixed by cloning
  factory inputs, then focused tests passed. Final gates recorded below.
- Frontend impact: **required**, [handoff 2026-10-27-01](../frontend-handoffs/2026-10-27.md#2026-10-27-01-resilient-service-supervision),
  Pending frontend review. Show local recovering/delivery warnings, preserve
  drafts and polling; no global editing lock from service availability.
- Limits/next: real appliance/reboot, physical link/WAN loss, TLS-broker and browser
  acceptance remain unverified. Shared recovery reopens workers rather than
  preserving protocol caches across failed attempts. No durable syslog replay,
  automatic prerequisite repair, relaxed packet/security checks or availability
  guarantee under process abort/OOM/power loss. Other privileged native suites
  remain unexecuted except the native workflow fixture above. No deployment or
  frontend delivery performed.
